# K-GroundControl 요구사항

- 상태: **초안 (승인 대기)** — 2026-10-24, PM 작성
- 이 문서가 정하는 것: 무엇을 만들고, 무엇은 만들지 않으며, 어떤 조건을 지키는가. 어디에 무엇을 둘지(구조)는 `specs/BASE.md`가, 기능 하나의 동작은 `specs/features/`가 정한다.
- 바탕 조사: PM 보관 문서 `.pm/research/inventory-ko.md`(QGC 기능 304개를 묶음 48개로 정리, 스택·차별점 조사 요약)과 원본 보고 9건. 저장소에는 넣지 않는다.

## 1. 한 줄 정의

PX4와 ArduPilot 기체를 위한 지상국(GCS). QGroundControl이 하는 일을 다 하면서, **처음 세팅하는 사람이 덜 헤매게** 하고, **ESC와 ELRS 수신기까지 한 프로그램에서** 설정하고 펌웨어를 굽는다.

## 2. 쓰는 사람과 상황

| 사람 | 상황 |
|---|---|
| 기체를 처음 조립해 세팅하는 사람 | FC·ESC·수신기 펌웨어를 올리고, 파라미터를 맞추고, 센서·조종기를 보정한다. QGC·Mission Planner에서 가장 많이 막히는 구간 |
| 비행을 운용하는 사람 | 연결하고, 상태를 보고, 미션을 짜서 올리고, 비행 중 명령을 내리고, 로그를 내려받는다 |
| 개발자(사람·AI) | 코드를 부분만 읽고 고친다. 전체를 읽지 않아도 된다 |

## 9. 검증 환경

- Linux(이 개발 머신): PX4 SITL(`docker run --network host px4io/px4-sitl`, UDP 14550), ArduPilot SITL(미리 빌드된 바이너리 또는 `sim_vehicle.py`, TCP 5760 / MAVProxy UDP 14550). GCS 둘이 한 머신이면 MAVProxy `--out`으로 포트 추가
- Windows: 사용자 PC에서 Actions 아티팩트 실행
- 실기: 사용자가 FC 하나 연결(사용자 계정을 `dialout` 그룹에 넣어야 함). ESC·ELRS 경로별 시험 장비는 그 기능 스펙 때 정한다

## 10. 미확인 (스펙 쓸 때 다시 확인)

- PX4 강제 시동 2989가 실제로 건너뛰는 검사
- PX4 1.18 SERIAL_CONTROL 비트뱅을 켠 보드 목록
- FC 뒤의 ELRS RX를 패스스루로 만지는 것
- Qt winrt TTS 엔진이 Windows 11 한국어 자연 음성을 쓰는지
- 영상 지연 수치(GStreamer/FFmpeg)
- Anthropic 토큰 수 정확값과 API 약관
- ArduPilot 파라미터 메타데이터 저장소(ParameterRepository)의 라이선스
- 전부 소스·문서 읽기 결과이며 QGC·ELRS·AM32 어느 것도 실제로 돌려 보지 않았다. Windows에서는 아무것도 확인하지 않았다
