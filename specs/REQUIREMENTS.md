## 1. 한 줄 정의

PX4와 ArduPilot 기체를 위한 지상국(GCS). QGroundControl이 하는 일을 다 하면서, **처음 세팅하는 사람이 덜 헤매게** 하고, **ESC와 ELRS 수신기까지 한 프로그램에서** 설정하고 펌웨어를 굽는다.

## 2. 쓰는 사람과 상황

| 사람 | 상황 |
|---|---|
| 기체를 처음 조립해 세팅하는 사람 | FC·ESC·수신기 펌웨어를 올리고, 파라미터를 맞추고, 센서·조종기를 보정한다. QGC·Mission Planner에서 가장 많이 막히는 구간 |
| 비행을 운용하는 사람 | 연결하고, 상태를 보고, 미션을 짜서 올리고, 비행 중 명령을 내리고, 로그를 내려받는다 |
| 개발자(사람·AI) | 코드를 부분만 읽고 고친다. 전체를 읽지 않아도 된다 |

## 4. 기능 요구 — QGC 수준 (R-Q)

묶음 번호(A1…E5)는 `inventory-ko.md`의 것. **R-Q 행 하나의 범위는 그 묶음에 속한 원본 ID 전부**(예: R-Q11 = E1~E5 = C-49~C-67 전부). 묶음에 들지 않은 원본 ID는 아래 "추가 ID" 칸으로 배정한다. 기능 스펙은 묶음 하나 또는 그 일부를 단위로 쓴다.

추가 ID 배정: R-Q1 ← C-5(블루투스), C-9(연결 보류), C-11(링크 품질·RADIO_STATUS), C-26(GCS 간 제어 넘기기, 미확인 10절) · R-Q2 ← F-16(끊김 처리), F-17(비행 상태 판정) · R-Q5 ← F-36(속도 변경), F-43(그리퍼), F-44(다중 기체 일괄 명령), F-45(가상 조이스틱) · R-Q6 ← F-57(지도 엔진·GeoMap), F-58(tlog 재생 화면) · R-Q7 ← P-10, P-11, P-15~P-20(미션 속도·카메라 구간·Plan 기본값), P-80~P-82(현재 항목 추적, 재개, AP go-to) · C-13(모의 링크)은 개발·테스트 도구로 BASE.md에서 다룬다(7절).

## 9. 검증 환경

- Linux(이 개발 머신): **PX4 SITL** — Docker 이미지 `px4io/px4-sitl`은 1.18 시험판 태그만 있어 1.18 검증에만 쓴다. 1.15~1.17 안정판은 PX4 소스를 **릴리스 태그로 받아 `make px4_sitl_sih`로 빌드**해 쓴다(빌드 시간·용량 미확인, 10절). UDP 14550. **ArduPilot SITL** — 미리 빌드된 바이너리(`firmware.ardupilot.org/<Vehicle>/stable-4.x.y/SITL_x86_64_linux_gnu/`) 또는 `sim_vehicle.py`, 버전 고정, TCP 5760 / MAVProxy UDP 14550. GCS 둘이 한 머신이면 MAVProxy `--out`으로 포트 추가. D17을 승인할 때 **SITL로 검증하는 버전**과 **연결만 시험하는 버전**을 나눈다
- Windows: 사용자 PC에서 Actions 아티팩트 실행(비공개 저장소라 GitHub 로그인 필요; 보존 기간·러너 분 한도는 확인 필요)
- 실기: 사용자가 FC 하나 연결(개발 머신 계정을 `dialout` 그룹에 넣어야 함). ESC·ELRS 경로별 시험 장비는 그 기능 스펙 때 정한다
