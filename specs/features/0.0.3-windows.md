### 3.3 로그 통로 — `LogFeed`(`platform/app/log`)
- 수명: `main`이 `QGuiApplication` 다음에 `LogFeed`를 만들고 `LogSink::attachFeed(LogFeed*, QStringList guardFilePrefixes)`로 붙인다(바탕 `app/log`는 기능 경로를 모르므로, 막을 경로는 `analyze` api `AppLogService::loopGuardPrefixes()`가 내고 — `qrc:/qt/qml/Kgc/Analyze/`와 `qrc:/qt/qml/Kgc/Ui/components/LogView.qml` — `main`이 `Composition::logGuardPrefixes()`(정적 함수; `analyze` api를 include하는 곳은 Composition 하나)로 받아 넘긴다); 종료 전(엔진 파괴 전) `LogSink::attachFeed(nullptr)`. `Composition`이 `LogFeed&`를 받아 `AppLogService`에 넘긴다. 다른 모듈은 이 참조로만 읽는다(파일을 다시 읽지 않음).
- 기록 한 줄 = `LogRecord{quint64 seq; LogLevel level; QString category, event, message, text}` — `text`는 파일에 쓴 줄에서 **끝 줄바꿈을 뺀 것**. `seq`는 1부터 하나씩.
- 스레드: `LogSink::write`는 자기 잠금 안에서 seq 없는 기록을 만들고, **잠금을 푼 뒤** `LogFeed::publish(record)`를 부른다. `publish`는 **자기 `QMutex` 안에서** seq를 매기고, 같은 잠금 안에서 고리 버퍼(용량 `kFeedCapacity = 2000`, `app/log/internal/Constants.h`; 시험용으로 생성자에 용량을 줄 수 있음)에 넣고, 같은 잠금 안에서 함수형 `QMetaObject::invokeMethod(this, [r]{ emit recordAdded(r); }, Qt::QueuedConnection)`으로 보낸다 — 그래서 버퍼 순서 = seq 순서 = 받는 순서. `publish` 안에서는 로그를 쓰지 않는다. `LogFeed`는 `main`이 엔진보다 먼저 만들어 `main`이 끝날 때까지 산다(떼어 낸 뒤에도 객체는 살아 있어 늦은 호출이 안전). `LogRecord`는 `Q_DECLARE_METATYPE`.
- `std::pair<QList<LogRecord>, quint64> recent() const`(버퍼 내용과 그 마지막 seq). 받는 쪽은 연결을 먼저 하고 `recent()`를 읽은 뒤, seq가 그 마지막 이하인 신호는 버린다(겹침·빠짐 없음). `int capacity() const`.
- **되돌이 막기**: (가) GUI 스레드가 `recordAdded`를 처리하는 동안(스레드 지역 표시) 생긴 `kgc.qt` 줄, (나) `QMessageLogContext.file`이 **`Composition`이 넘긴 막을 경로 접두** 중 하나로 시작하는 `kgc.qt` 줄은 파일에는 쓰지만 `LogFeed`로는 내보내지 않는다(Qt 메시지 처리기가 context를 LogSink로 넘김). 로그 창이 경고를 낳고 그 경고가 또 줄이 되는 고리 차단(다음 프레임에 만들어지는 delegate의 경고도).

### 3.4 창 자리 — `WindowPlacement`(`platform/ui`)
- `struct ScreenInfo{QString name; QRect available;}`(같은 헤더). 목록 첫째가 주 화면(`QGuiApplication::screens()` 순서; Qt가 첫째를 주 화면으로 줌).
- 순수 함수 `Placement restorePlacement(const QString& saved, const QList<ScreenInfo>& screens, QSize defaultSize)` → `Placement{int screenIndex; QRect geometry}`, 그리고 `QString savePlacement(const QString& screenName, QRect geometryInScreen)`.
- 저장 꼴: `"<화면 이름>|x|y|w|h"`, x·y는 **그 화면 `available` 왼쪽 위 기준**(논리 픽셀). 읽을 때는 **오른쪽부터 4칸**을 떼고 나머지를 이름으로(이름에 `|`가 있어도 됨). 같은 이름의 화면이 둘이면 첫째.
- 복원: 저장 화면이 있으면 그 화면, 없거나 값이 비었거나 깨졌으면 주 화면 가운데 `defaultSize`. 어느 쪽이든 마지막에 같은 **끌어오기 식**을 거친다(화면 기준 좌표, `A` = 그 화면 `available`, `M = kTitleBarMargin = 32`, `platform/ui/internal/Constants.h`): `w = min(w, A.w)`, `h = min(h, A.h − M)`, `x = clamp(x, 0, A.w − w)`, `y = clamp(y, M, A.h − h)`.
- 적용 순서: `setScreen` → `setGeometry` → `show`. 저장은 창 상태가 `Windowed`일 때만(최소화·최대화 중엔 안 함).

### 3.5 별도 창의 주인·열기·닫기·종료
- 공용 도우미 **`SeparateWindow`**(`platform/ui` api, QObject): 창 만들기(루트 문맥, `visible:false`, 부모 = 자기), 화면 목록 → `ScreenInfo`, 자리 복원·적용(setScreen→setGeometry→show), 다시 열기(showNormal→raise→requestActivate), 화면 기준 저장 변환, `aboutToQuit` 처리를 한 곳에서 한다. 저장값 읽기·쓰기는 생성자에 받은 두 함수(그 기능의 설정 접근자)로. 두 컨트롤러는 이것을 하나씩 갖고 같은 코드를 되풀이하지 않는다.
- 각 기능의 컨트롤러(`AppLogController`, `SecondPanelController`, `ui/`)가 자기 `SeparateWindow` 하나를 갖고, 창은 그 `SeparateWindow`가 만든다(창의 부모 = `SeparateWindow`, `SeparateWindow`의 소유 = 컨트롤러 하나 — 값 멤버면 QObject 부모를 따로 주지 않음). 처음 `open()` 때 같은 엔진의 **루트 문맥**에서 `visible: false`로 만들고, **transientParent 없음**, 자리를 복원(§3.4)한 뒤 `show()`.
- 다시 `open()`: 최소화돼 있으면 `showNormal()` 다음 `raise()`·`requestActivate()`(새로 만들지 않음). 창의 닫기 = 숨기기(다음에 다시 씀).
- Q_PROPERTY `window`(`QQuickWindow*`, 없으면 null)와 `Q_INVOKABLE open()`. `BottomActionSlot`의 receiver는 이 컨트롤러, method는 `open`.
- 자리 저장: 창 QML의 `TimerBox`(간격은 컨트롤러의 `Q_PROPERTY(int saveDelayMs CONSTANT)` = 기능 `Constants.h`의 `kSaveDelayMs = 500`에 묶음 — QML에 500을 적지 않음)가 x·y·width·height가 바뀔 때마다 다시 시작해 끝나면 `controller.savePlacement()`; 창 `closing`과 `QCoreApplication::aboutToQuit`에서도 **바로** 저장.
- 종료: `Composition`이 셸 창의 `closing`을 `QCoreApplication::quit()`에 잇는다(shell은 기능을 모른 채). 각 `SeparateWindow`가 `aboutToQuit`에서 자리를 저장하고 자기 창을 닫는다. 다음 실행 때 저절로 열지 않는다.
- 크기: 별도 창도 **메인 창의 `Theme.uiScale`을 그대로 따른다**(이번 범위; 창별 배율은 §7).
- 기본 크기: 로그 창 960×600, 세컨드 패널 1280×800(각 기능 `Constants.h`).

### 3.9 시험 붙이는 법·실행 환경
- 0.0.2 §3.9 그대로, 단 setup이 바뀐다: `applicationAvailable`이 프로세스에 하나인 `LogFeed`를 만들고, 격리된 데이터 폴더로 `LogSink::install` 한 뒤 `attachFeed`; `qmlEngineAvailable`의 `Composition`에 그 feed를 넘긴다(0.0.1·0.0.2 시험 setup도 이 인자만 고침). 창은 `appLogController.window`·`secondPanelController.window`로 찾는다(단추를 누른 뒤).
- **로그 쓰기 도우미**: 시험 setup(저장소 밖 `.pm/tests` C++)이 `KGC_LOG_*`로 INFO·WARN·ERROR 줄을 쓰는 작은 QObject를 컨텍스트에 둔다(시험 전용 카테고리·사건; 제품 코드에 넣지 않음). QML `console.warn`이 만드는 `kgc.qt` WARN 줄도 써도 된다.
- **두 화면 흉내**: `:99`는 화면 하나. 화면 복원은 `tests/test_window_placement.cpp`가 화면 목록을 넘겨 본다.
- **T13(종료)**: QML 시험 안에서는 할 수 없다(시험 실행기가 끝남). 실제 실행 파일을 띄우고 작은 Xlib 스크립트(python3 `ctypes`로 libX11)로 셸 창에 `WM_DELETE_WINDOW` ClientMessage를 보낸 뒤, 프로세스가 끝나는지와 로그의 `shell.AppStopped`를 본다.
- 시험 파일은 `.pm/tests/0.0.3/`에 보관.
