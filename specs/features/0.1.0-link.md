## 1. 목적
앱이 처음으로 진짜 기체에 붙는다. 사용자가 상단바에서 UDP 14550이나 시리얼 포트를 골라 연결하면, 기체를 발견하고 펌웨어를 판별해 **계기·개요 탭·하단 기체 칩**에 실제 값을 보여 준다. 이번 버전이 기체로 보내는 것은 **GCS 하트비트와 스트림 요청뿐**이다. 기체를 움직이는 명령은 없다.

## 2. 사용자 결정 (2026-10-31)
1. 연결 방식은 UDP와 시리얼 둘 다.
2. 연결은 상단바에서 수동으로. 자동 감지·링크 저장은 뒤 버전.
3. 화면은 계기 + 개요 탭 + 하단 기체 칩. 상세·메시지 탭, 하단 센서·배터리·RSSI 칩은 뒤 버전.
4. 시험용 FC는 빌린 것이라 없어질 수 있다. **합격 기준은 SITL만으로 통과해야 하고**, FC 시험은 있으면 하는 추가 확인이다(§8).

### 5.2 Scheduler
`registerTask(QString name, std::chrono::milliseconds period, QObject* owner, QObject* context, std::function<void()> fn)`. `fn`은 `context`의 스레드에서 돌고, `owner`가 사라지면 작업도 끝난다. `owner`와 `context`는 같은 스레드에 있어야 하고(다르면 프로그래밍 오류), 같은 이름도 프로그래밍 오류다. 기체별 작업 이름에는 sysid를 붙인다(`gcsHeartbeat.<sysid>`, `linkLoss.<sysid>`).

### 5.3 링크
- `LinkConfig`: 종류(Udp·Serial), 포트 이름, 속도. UDP 수신 포트는 고정값 14550, `0.0.0.0`에 묶는다.
- `LinkManager`(GUI 스레드)는 링크를 **한 번에 하나** 가진다.
  - `Result<void> connectLink(config)`: 동기 실패는 `LinkError::AlreadyConnected`뿐. 열기는 워커에서 하고 결과는 시그널로 온다.
  - `disconnectLink()`.
  - 성공한 `connectLink`는 끝 신호를 **정확히 하나** 낸다. 사용자가 끊거나(열기 중 취소 포함) 포트를 잃으면 `linkClosed`, 사용자가 끊지 않았는데 열기가 실패하면 `linkFailed`. 열기 중 `disconnectLink()`는 그 사이 열기가 실패해도 `linkClosed(id, nullopt)` 하나로 끝나고, 이때는 `linkOpened`가 앞서지 않을 수 있다. `LinkService`는 `linkClosed`를 받으면 언제나 `Idle`(오류가 있으면 `Failed`)로 간다.
  - 시그널: `linkOpened(int linkId)`, `linkFailed(ErrorCode)`, `linkClosed(int linkId, std::optional<ErrorCode>)`, `messageReceived(int linkId, mavlink_message_t)`, `portsChanged()`.
- 링크 상태(`link` 기능의 `LinkService`): `Idle / Opening / Open / Failed`.
- 링크마다 워커 `QThread`. 워커에서 I/O·파싱·`dropV1NonHeartbeat`를 하고 `messageReceived`를 큐드로 낸다(BASE §5). 송신은 워커로 큐드 전달.
- UDP의 상대 주소는 **마지막으로 데이터그램을 보낸 주소**. 받은 적이 없으면 송신은 조용히 버린다.
- 오류 대응: `DeviceNotFoundError`→`PortOpenFailed`, `PermissionError`→`PermissionDenied`, `OpenError`→`PortBusy`, 그 밖의 열기 실패→`PortOpenFailed`, UDP bind 실패→`UdpBindFailed`. `PermissionDenied`의 문구는 "포트를 열 권한이 없거나 다른 프로그램이 쓰고 있어요."(Linux에서 사용 중인 포트가 권한 오류로 올 수 있음). 시리얼이 뽑히거나 쓰기 오류가 나면 `PortLost`로 `linkClosed`, 재접속은 하지 않는다.
- 시리얼 목록: `Scheduler` 1Hz 작업으로 `QSerialPortInfo`를 읽어 바뀌면 `portsChanged`. 표시는 `<포트 이름> (<설명>)`.
- 부팅 설정 `--extra-serial <경로>`(§10-5)를 주면 그 경로를 목록 맨 뒤에 더한다. 가상 시리얼 시험용이다.
- MAVLink v1 프레임은 HEARTBEAT만 쓰고 나머지는 버린다(R-Q2). `MavlinkParser`는 전부 해석하고 `isV1`을 내놓으며, 거르기는 순수 함수 `dropV1NonHeartbeat`가 한다. PX4는 v2 프레임을 받으면 v2로 바꾸므로 GCS 하트비트는 항상 v2로 보낸다.

### 5.4 기체 발견과 수명
- `VehicleRegistry`가 `messageReceived`를 받는다. **compid 1이고 `autopilot ≠ INVALID`인 HEARTBEAT**의 sysid가 처음이면 `Vehicle`을 만들고 `FirmwarePluginFactory`로 플러그인을 고른다. 판정은 `VehicleSelection.h`의 순수 함수. 다른 compid·GCS·짐벌 메시지는 무시한다.
- `Vehicle`은 만들어진 링크의 `LinkConfig` 복사본을 `linkConfig()`로 내놓는다.
- 같은 sysid의 `autopilot`이 달라지면 기체를 지우고 새로 만든다(BASE §8).
- 활성 기체는 처음 생긴 기체. 지워지면 남은 기체 중 sysid가 가장 작은 것, 없으면 없음(`activeChanged`).
- `linkClosed`가 오면 기체를 전부 `vehicleRemoved` → `deleteLater`.
- 하트비트가 끊겨도(3500ms) 기체는 남기고 `lost`만 켠다. 다시 오면 끈다. 판정은 `isLinkLost(lastHeartbeatMs, nowMs)`(`nowMs − last ≥ 3500`), 호출은 `VehicleStateOwner`의 1Hz `Scheduler` 작업.

### 5.5 상태 묶음 (BASE §5의 부분집합)
`VehicleStates`의 프로퍼티 `link`·`arming`·`attitude`·`position`·`gps`·`battery`·`capabilities`, 시그널 `linkChanged`·`armingChanged` 등. 구조체 이름은 comm의 `Link`와 겹치지 않게 전부 `<이름>Bundle`(§10-6). 첫 메시지 전 숫자 필드는 NaN, 정수는 −1, 화면은 `—`.

| 묶음 | 필드 | 출처 |
|---|---|---|
| `LinkBundle` | `connected`, `lost`, `lastHeartbeatMs` | HEARTBEAT, 끊김 판정 |
| `ArmingBundle` | `armed`, `modeId`, `modeName` | HEARTBEAT(`base_mode`, `custom_mode`) + 플러그인 |
| `AttitudeBundle` | `rollDeg`, `pitchDeg`, `yawDeg`(0~360 정규화) | ATTITUDE |
| `PositionBundle` | `latDeg`, `lonDeg`, `altAmslM`, `altRelM`, `groundSpeedMs`, `climbMs`, `headingDeg`(`hdg` 65535→NaN) | GLOBAL_POSITION_INT |
| `GpsBundle` | `fixType`, `satellites`(255→−1), `hdop`(65535→NaN) | GPS_RAW_INT |
| `BatteryBundle` | `voltageV`, `currentA`, `remainingPct` | SYS_STATUS (UINT16_MAX·−1·−1 → NaN·NaN·−1) |
| `CapabilitiesBundle` | `vehicleType`, `firmwareName` | HEARTBEAT, 플러그인 |

`Battery[]` 목록은 이번에 만들지 않는다(§10-7). 해석은 `internal/updaters/<Bundle>Updater`의 순수 함수.

### 5.6 펌웨어 플러그인 (데이터와 순수 함수만)
- `displayName()`: `PX4`·`ArduPilot`·`MAVLink`(generic).
- `modeName(customMode, mavType) -> QString`: 모르면 빈 문자열. PX4 표는 main·sub 모드. AP 표는 Copter만이고 `MAV_TYPE`이 쿼드·헥사·옥토·트라이·헬리·동축·도데카·데카일 때 쓴다. 이름은 번역하지 않는 공식 영어다. 화면은 비면 `모드 %1`.
- `streamRequests() -> QList<StreamRequest>`(`{streamId, rateHz}`): PX4·generic은 비어 있다. ArduPilot은 `REQUEST_DATA_STREAM`으로 `EXTENDED_STATUS` 2Hz, `POSITION` 4Hz, `EXTRA1` 10Hz.

### 5.7 송신
`VehicleSender`(기체마다 하나, GUI 스레드)가 유일한 문이다.
- `OutboundKind`는 여섯 값 모두 정의하고, 이번 버전은 `Other`만 쓴다. `WorkLock`·`RebootWindow` 검사는 그 모듈이 생기는 버전에 더한다(§10-11).
- `send(OutboundKind, PackFn)`. `PackFn`은 `void(uint8_t sysid, uint8_t compid, uint8_t chan, mavlink_message_t&)`. Sender가 GCS id와 링크 채널을 넘기므로 패킹은 한 번, 항상 v2다. 결과는 링크 워커로 큐드 전달.
- 기체가 생기면 1Hz `Scheduler` 작업 `gcsHeartbeat.<sysid>`로 HEARTBEAT(`MAV_TYPE_GCS`, `MAV_AUTOPILOT_INVALID`)를 보낸다(§10-4).
- `streamRequests()`는 **기체가 생길 때와 `lost`가 참→거짓으로 바뀔 때마다** 보낸다(SITL이 재시작된 뒤 스트림 복구).

### 5.8 상단바 (`features/link`)
- 슬롯에 실제 항목 등록 API를 더한다: `TopbarSlot::registerItem(id, order, area, group, component)`, `StatusChipSlot::registerItem(id, order, side, component)`. `component`가 있으면 `TopbarEntry`는 `Loader`로 그 QML을 띄우고, `StatusChipEntry`는 루트를 `Loader` 기반 `Item`으로 바꿔 칩 높이를 유지한다. 자리 표시 경로의 모습은 그대로다. 기여 QML이 자기 objectName을 직접 정한다.
- `Composition`은 `link.port`·`link.baud`·`link.connect`·`link.connection` 자리 표시를 지우고, `link`가 같은 id·순서로 등록한다.
- `Theme`에 크기 토큰 `topbarFieldWidth`를 더한다.

| id · objectName | 부품 | 동작 |
|---|---|---|
| `link.port` · `topbar_link.port` | `ComboField`(`label` 없음, `displayText: qsTr("포트: %1")`) | 첫 항목 `UDP 14550`, 뒤로 시리얼 목록. `Idle`·`Failed`가 아니면 잠김. 선택은 컨트롤러가 **포트 이름**으로 들고, 목록이 바뀌어도 유지하며, 사라지면 첫 항목 |

### 5.10 계기와 개요 탭 (`features/vehicleInfo`)
`VehicleInfoController`가 `VehicleRegistry::activeChanged`에 다시 묶이고, 묶음을 표시값으로 옮긴다. 계기 넷의 `available`은 활성 기체가 있고 `lost`가 아닐 때 참.

| 계기 속성 | 값 |
|---|---|
| `roll`·`pitch` | `rollDeg`·`pitchDeg` |
| `heading` | `yawDeg`(`headingDeg`는 없을 수 있음) |
| `speed`·`altitude`·`climbRate` | `groundSpeedMs`·`altRelM`·`climbMs` |
| `flightMode`·`armed` | 모드 이름·참거짓 |
| `batteryVoltage`·`batteryPercent` | `voltageV`·`remainingPct`(−1→NaN) |
| `gpsFix`·`satellites` | 개요의 fix 이름·`satellites`(−1→NaN) |
| `homeDistance`·`linkQuality`·`hasCompass` | 기본값 유지 |
| `modelKind` | `quad` 고정 |

| 개요 줄 | 값 |
|---|---|
| 상단 `EmptyState` | 활성 기체가 없을 때만. 안내 문구를 "상단바에서 포트를 고르고 연결해요."로 바꾼다 |
| 시동 · 모드 | `시동` 또는 `해제` · 모드 이름 |
| 배터리 잔량 + `ProgressLine` | `%1%`, 없으면 `—` |
| 전압 · 전류 | `%1 V · %2 A`(소수 1자리), 없으면 `—` |
| 고도(상대 / AMSL) | `%1 m / %2 m`(소수 1자리) |
| 속도(수평 / 수직) | `%1 m/s / %2 m/s`(소수 1자리) |
| GPS | `<fix 이름> · 위성 %1`. `fix_type` 0~1 없음, 2 2D, 3 3D, 4 DGPS, 5 RTK Float, 6 RTK Fixed, 7 이상 3D |
| 홈까지 거리 | `—` 유지 |
| 링크 · 연결 | 활성 기체의 `linkConfig()`로 `UDP 14550` 또는 `<포트> @ <속도>`. 활성 기체가 없으면 `없음` |
| 비행 시간 · 거리 | `— · —` 유지 |

`lost`이면 값은 마지막 값을 유지하고 계기만 `available=false`.

### 5.11 컨트롤러와 문구 (§10-1)
- 새 컨트롤러 `LinkController`, `VehicleInfoController`는 컨텍스트 프로퍼티가 아니라 **형이 있는 QML 싱글턴**으로 낸다.
  - `QML_ELEMENT` + `QML_SINGLETON` + `static create(QQmlEngine*, QJSEngine*)`. 객체는 `registerUi`가 서비스를 부모로 만들고 정적 포인터에 둔다(`loadShell()` 전). `create()`는 포인터를 단언하고 `CppOwnership`을 정한다.
  - `ui/XController.h`를 `qt_add_qml_module`의 `SOURCES`에 넣고 `PRIVATE ui`를 유지한다. `src/main`에 `Q_IMPORT_QML_PLUGIN(Kgc_LinkPlugin)`과 링크 추가.
  - QML은 `import Kgc.Link`·`import Kgc.VehicleInfo`를 **명시**한다(qmllint가 형으로 풀게).
  - 기존 컨트롤러는 이번에 건드리지 않는다.
- **문구는 QML이 만든다.** 컨트롤러는 상태만 낸다(`connectionState` 열거, `sysid`, `firmwareName`, 숫자값). 번역 전환이 되도록 QML이 `qsTr`로 조립한다. 실패 글자는 `Q_INVOKABLE failureText()`를 `{ translator.language; return … }` 방식으로 읽는다. `i18n/kgc_en.ts`에 전부 넣는다.

## 6. 자동 검사 (먼저 넣는다)
구현 **첫 단계**로 BASE §14의 0.1.x 검사를 `tools/check/checks/`에 넣는다: MAVLink include(`<kgc/app/constants/mavlink.h>`는 대상 아님), 펌웨어 분기, 송신, 타이머, 고정값, 설정 키, 로그·오류, 문자열(C++), 이름 중복, 바깥 접점(시리얼·환경 변수).
- 고정값 검사는 `src/`만 보고 `Constants.h`, `platform/app/constants/`, `ModuleId.h`, 생성 코드는 제외한다.
- 이름 중복 검사는 모듈마다 있어야 하는 `registerUi`, `make`, `errorText`를 제외한다(§10-12).
- 기존 코드가 걸리면 같은 단계에서 고치고 보고한다.

qmllint: 전체 빌드 뒤 `linux.yml`에서 `qmllint @build/linux-release/src/features/<id>/.rcc/qmllint/kgc_<id>.rsp --unqualified disable --max-warnings 0`. `vehicleInfo`는 S6에서, `link`는 S5에서 더한다.
