## 1. 목적
좌 메뉴 **펌웨어 세팅**에서 PX4·ArduPilot 부트로더가 있는 FC에 펌웨어를 굽고, 재연결로 실제로 올라갔는지 확인한다. 이번 버전이 기체를 움직이는 명령은 없다. 기체로 보내는 새 명령은 재부팅(부트로더)과 `AUTOPILOT_VERSION` 요청뿐이다.

## 2. 사용자 결정 (2026-11-01)
1. 펌웨어 업그레이드를 수동 기체 설정보다 먼저 한다. 수동 기체 설정은 0.3.0.
2. 출처는 셋: ArduPilot 공식 목록, PX4 GitHub Releases, 파일 직접 선택(`.px4`·`.apj`). 외부 플래시 이미지(`extf`)를 지원한다.
3. Betaflight와 DFU 굽기는 대상이 아니다. PX4 `master`, SiK, 부트로더 자체 업데이트는 뺀다.
4. 맞는 펌웨어가 하나면 자동 선택, 여럿이면 기본 선택 없이 사용자가 고름, 없으면 파일 선택 안내. 파일의 보드 ID가 다르면 굽지 않고 우회 옵션도 없다. 실행은 길게 눌러 확인. 이름이 달라도 막지 않는다.
5. 부트로더 진입은 Mission Planner 흐름: 포트 선택 → 이미 부트로더면 진행 → HEARTBEAT 3초 대기 후 재부팅 명령 → 실패하면 뽑았다 꽂기 안내 → 30초 탐색. 단, 탐색은 고른 포트와 새로 나타난 포트만 한다.
6. 검증에 실패하면 FC를 부팅시키지 않는다.
7. 끝나면 재부팅하고 최대 60초 안에 다시 연결해 펌웨어 종류와 버전을 비교해 보여 준다. 다르면 경고만 한다.
8. 시험에 빌린 KOA FC를 써도 된다. 굽기 전에 FC의 현재 상태(파라미터, 펌웨어)를 저장소 밖에 백업하고, 시험 뒤 되돌릴 수 있게 해 둔다.

### 5.2 `app/scheduler` `Timeout`
`Timeout(QString name, QObject* parent)`: `start(std::chrono::milliseconds)`, `stop()`, 시그널 `expired()` 한 번. 이름은 로그에만 쓴다. `QTimer`는 이 클래스와 `Scheduler` 안에만 둔다.

### 5.3 `app/job`
BASE §9.4를 따른다. `Job(OperationKind kind, QObject* parent)`, 프로퍼티 `state`, `stepName`, `progress`(0~1, 모르면 −1), `etaSeconds`(모르면 −1), `cancellable`, `errorCode`, `errorText`.
- 함수: `setStep(key)`, `setProgress(value)`, `setCancellable(bool)`, `succeed()`, `fail(ErrorCode, QString text)`, `cancel()`(시그널 `cancelRequested`만 낸다), `finishCancelled()`(상태 `Cancelled`, `finished`는 `make(JobError::Cancelled)`), `hold(Releaser)`.
- `finished(Result<void>)`는 한 번만 난다. 끝날 때 해제 핸들을 역순으로 부른다.
- `stepName`은 번역 원문 키이고 `JobView`가 `qsTranslate("Job", key)`로 그린다. C++에서는 `QT_TRANSLATE_NOOP("Job", …)`.
- `etaSeconds`는 시작 뒤 경과와 진행률로 계산하고, 진행률이 1% 미만이면 −1.
- `OperationKind`는 BASE §9.2 표의 값을 모두 둔다.

`platform/ui/components/JobView.qml`: `job`을 받아 단계 글자, `ProgressLine`, 남은 시간(`약 %1초 남음`), `취소` 단추(`cancellable`일 때만)를 보여 준다. 프로퍼티 `showError`(기본 참)가 참이면 `errorText`를 빨간 글자로 보여 준다.

### 5.4 `app/net`
- `Http`(GUI 스레드, 전역 하나, `Composition`이 만든다). `QNetworkAccessManager`는 이 모듈 안에만 둔다. `https://`가 아닌 주소는 `HttpError::NotHttps`로 바로 실패한다.
- `HttpRequest* get(QUrl, HttpOptions)`: 결과는 메모리. `HttpRequest* download(QUrl, QString path, HttpOptions)`: `path + ".part"`에 쓰고 끝나면 이름을 바꾼다. 시그널 `progress(received, total)`, `finished(Result<QByteArray>)`(다운로드는 빈 값), 함수 `abort()`.
- `HttpOptions`: `timeout`(기본 30초, 무응답 시간), `retries`(기본 2), `headers`. 리다이렉트는 HTTPS끼리만 따라간다(순수 함수 `redirectAllowed(from, to)`). `User-Agent`는 `K-GroundControl/<버전>`.
- 시그널 `onlineChanged`는 만들되 값은 마지막 요청의 성공 여부다.
- `Result<QByteArray> gunzip(const QByteArray&)`: 순수 함수.

### 5.5 `comm/rawport`와 포트 목록
- `ByteStream`(인터페이스, **작업 스레드에서 막아서 쓴다**, §10-2): `Result<void> write(QByteArray)`, `Result<QByteArray> read(int count, std::chrono::milliseconds timeout)`, `void clearInput()`, `bool canControlLine() const`, `Result<void> setBaud(int)`, `Result<void> setDtrRts(bool dtr, bool rts)`.
- `RawPort : ByteStream`: `QSerialPort`를 만든 스레드에서 쓴다. `static Result<std::unique_ptr<RawPort>> open(QString portName, int baud)`. 115200 8N1, 흐름 제어 없음. 포트 오류는 `PortError::Lost`, 시간 초과는 `PortError::Timeout`.
- `PortRegistry`(GUI 스레드, 전역 하나, `Composition`이 만들고 `LinkManager`에 참조로 넘긴다): `Result<Token> claim(QString portName, Owner owner)`, `release(Token)`, `Owner ownerOf(QString)`. `Owner`는 `None, Link, Lease`. 이미 주인이 있으면 `PortError::Busy`.
- `PortLease`: `static Result<PortLease> acquire(PortRegistry&, QString portName)`. 이동만 되고 GUI 스레드에서만 쓴다. 소멸하면 `release`한다. 링크가 쥔 포트는 `Busy`(일시 정지는 뒤 버전).
- `LinkManager` 변경: 생성자에 `PortRegistry&`. 시리얼 `connectLink`는 워커를 만들기 전에 `claim(port, Link)`을 하고, 실패하면 동기 실패 `LinkError::PortBusy`. 링크가 끝날 때 `release`. `refreshPorts()`를 public으로. 새 함수 `PortInfo portInfo(QString name)`(`{manufacturer, product}`, 없으면 빈 값).
- **`--extra-serial`을 반복 가능하게 한다**: `BootOptions`와 `LinkManager`가 `QStringList`를 받는다. 각 경로는 **파일이 있을 때만** `ports()`에 든다. 0.1.1 §5.7의 "경로는 목록에 항상 있다"를 대체한다. 시험은 경로를 미리 선언하고 `socat pty,link=<경로>`로 나타나게, 지워서 사라지게 한다.

### 5.6 `vehicle/safety` `ArmedPolicy`
`Decision check(OperationKind, VehicleScope)`. `Decision`은 `Allow, AllowWithWarning, Deny`. `VehicleScope`는 `One(Vehicle*)`, `Any`. 생성자에 `VehicleRegistry&`. 표는 BASE §9.2이고 순수 함수 `decide(kind, armed)`.

### 5.7 `vehicle/command` `CommandQueue`
- `CommandQueue(SendFn send, int sysid, QObject* parent)`, `SendFn = std::function<Result<void>(OutboundKind, VehicleSender::PackFn)>`. `Vehicle`이 기체마다 하나 만들고 `Vehicle::commands()`로 낸다.
- `void send(CommandLong command, CommandOptions options, std::function<void(CommandResult)> done, QObject* context)`. `CommandLong`은 `command`, `param1~7`, `targetCompid`(기본 1). `CommandResult`는 `{optional<MAV_RESULT>, 실패 이유 Timeout·Gone·NoLink}`. `CommandOptions` 기본 `{timeout = kAckTimeout 1200ms, retries = 3}`(`app/constants/mavlink.h`에 값 추가).
- 한 번에 하나씩 보낸다. 시간 재기는 실제 송신부터. 같은 명령 번호의 `COMMAND_ACK`로 끝난다. `MAV_RESULT_IN_PROGRESS`는 시간을 다시 재고 끝으로 보지 않는다. 재시도는 `confirmation`을 1씩 올린다. `OutboundKind::Command`로 보낸다.
- `Vehicle::consume`이 `COMMAND_ACK`를 큐로 넘긴다. `Vehicle::stop()`은 큐를 먼저 끝내고(`Gone`) sender를 지운다.
- 기체가 생기면 `Vehicle`이 `MAV_CMD_REQUEST_MESSAGE`(`param1 = 148`)를 `{retries = 0}`으로 한 번 보낸다. 실패해도 조용히 넘어간다.

## 6. 동작
화면 배치와 문구는 `specs/ui/fcflash.html`을 따른다.

### 6.1 상태
`Step`은 `Board, Firmware, Confirm, Flash`. `Phase`:

| Phase | Step | 뜻 |
|---|---|---|
| `Idle` | Board | 포트 고르는 중 |
| `Probing` | Board | 고른 포트 확인 중 |
| `Rebooting` | Board | 재부팅 명령 보낸 뒤 |
| `WaitReplug` | Board | 뽑았다 꽂기 기다림, 남은 초 `secondsLeft` |
| `PickPort` | Board | 부트로더 포트가 둘 이상 |
| `Ready` | Firmware·Confirm | 보드 정보를 읽고 포트를 쥠 |
| `Flashing` | Flash | Job 진행 중 |
| `Reconnecting` | Flash | 부팅 뒤 재연결 중 |
| `Done`·`Mismatch`·`NoReturn` | Flash | 끝 |
| `Failed` | Board 또는 Flash | 실패, `canRetry`, `failureText()` |

### 6.2 포트 소유
- 임대(`PortLease`)와 `RawPort`는 `Ready`부터 서비스가 쥔다. 임대는 GUI 스레드, `RawPort`는 `FlashWorker` 스레드에 있다.
- 굽기 시도마다 새 `Job`을 만든다. 임대는 `job.hold`로 넘기지 않는다(§10-9). Job은 검증 성공, 실패, 취소에서 끝난다. 재부팅·재연결 행은 `Phase`가 그린다.
- 임대 해제는 `boot()`, `처음으로`, `취소하고 FC 부팅`, 포트 유실 때만이고, **워커가 포트를 닫았다는 큐드 신호 `portClosed`를 받은 뒤** 놓는다.

### 6.3 1단계: 보드 확인 (`beginProbe(portName)`)
1. `ArmedPolicy::check(FcFlash, Any)`가 `Deny`면 시작하지 않는다(`Armed`).
2. `LinkManager`에 링크가 있고 UDP이거나 다른 포트면 시작하지 않는다(`OtherLink`).
3. `LinkManager::refreshPorts()` 뒤 포트 목록을 `known`으로 기억한다.
4. 고른 포트에 링크가 없으면 임대 + `RawPort`로 열어 `sync` + `identify`를 시도한다. 성공하면 `Ready`. 아니면 포트를 닫고 임대를 놓는다.
5. 링크가 없으면 `connectLink`로 그 포트를 임시로 연다(115200). 링크가 이미 있으면 그대로 쓴다.
6. `kHeartbeatWait` 3초 안에 기체가 나타나면 `CommandQueue`로 `MAV_CMD_PREFLIGHT_REBOOT_SHUTDOWN`(`param1 = 3`)을 `{retries = 0}`으로 보낸다. `ACCEPTED`면 `disconnectLink()` 하고 `Rebooting`.
7. 기체가 없거나 명령이 실패하면 `disconnectLink()`. `linkClosed`를 받은 뒤, 링크가 처음부터 있던 경우에 한해 고른 포트에 4번을 한 번 해 본다(이미 부트로더인 포트에 링크를 열어 둔 경우). 아니면 `WaitReplug`.
8. 탐색은 `Scheduler` 작업 `fcFlashScan` 500ms. 매번 `refreshPorts()`로 후보를 다시 구한다. 후보는 ① `known`에 없던 포트, ② 고른 포트가 한 번 사라졌다가 돌아왔으면 그 포트. 돌아온 뒤 500ms가 지난 포트만 시도한다. 회차가 끝나기 전에는 새 회차를 시작하지 않는다.
9. 한 회차는 **그때의 후보 전부를 차례로 `sync` + `identify`하고** 판정한다. 하나면 `Ready`, 둘 이상이면 `PickPort`(응답한 포트를 모두 쥐고 있고, 고르면 나머지를 부팅 없이 닫는다), 없으면 다음 회차에 다시 한다. `FlashWorker`는 후보별 `RawPort`를 여럿 쥘 수 있다.
10. `Rebooting`에서 `kRebootWait` 8초 안에 응답이 없으면 `WaitReplug`로 바꾼다. `WaitReplug`는 들어온 때부터 `kBootloaderWait` 30초를 센다. 넘으면 `Failed`(`BootloaderNotFound`, `canRetry`, `다시 하기`는 `retryProbe`).

`known`에 있던 다른 포트에는 바이트를 보내지 않는다.

### 6.4 `Bootloader` (ByteStream 위, 작업 스레드)
조사 §Q1의 순서를 따른다. 단계마다 `Result`를 돌려준다. 모든 읽기는 100ms 조각으로 나눠 중단 플래그를 확인한다.
- `sync()`: `0x21 0x20` → `0x12 0x10`. 300ms씩 3번.
- `identify()`: `GET_DEVICE`(`0x22 arg 0x20`) 1 부트로더 판, 2 보드 ID, 3 보드 판, 4 플래시 크기, 6 외부 플래시 크기(판 5 이상, 실패하면 0). **판이 3~20 밖이면** `BadBootloaderRevision`.
- `erase(progress)`: 시간 제한 20초, 플래시가 2000 KB를 넘으면 1 MB마다 4초 더한다. 읽기 조각마다 경과 시간 비례로 진행률을 낸다.
- `program(image, progress)`: `0x27 len data 0x20`, 묶음 252바이트, 4의 배수. 이미지는 4바이트 배수로 `0xFF`를 덧붙인다. 재시도 없음.
- `verify(image)`: `0x29 0x20`, 시간 제한 5초. 비교 값은 이미지 + `0xFF` 채움을 **부트로더가 알려 준 플래시 크기까지** `crc32Bootloader`로 계산한다.
- `extfErase/extfProgram/extfVerify`: 조사 §Q4. 외부 이미지가 있으면 내부보다 먼저 한다. `extf_image_size > 0`인데 외부 플래시가 그보다 작으면 굽기 전에 `TooLarge`.
- `image_size`가 0이면 내부 지우기·쓰기·검증을 건너뛴다.
- `boot()`: `0x30 0x20`, 응답을 기다리지 않는다.
- **검증 실패 시 `boot()`를 부르지 않는다.**

### 6.5 2단계: 펌웨어 선택
- 위 칸에 보드 정보: `LinkManager::portInfo`의 제조사·제품 이름(없으면 `—`), 보드 ID, 플래시 KB, 부트로더 판.
- `PillGroup`: `PX4`, `ArduPilot`, `파일 선택`. 기본은 `PX4`.
- **PX4**: `GET https://api.github.com/repos/PX4/PX4-Autopilot/releases?per_page=30`. 초안과 프리릴리스를 빼고 최신 순. 버전 콤보의 첫 항목은 `<태그> (안정판)`. 후보는 `px4-boards.json`에서 보드 ID가 같은 `prefix`에 대해 자산 `<prefix>_<꼬리표>.px4` 전부, 꼬리표 `bootloader`는 뺀다. 표시는 `<prefix> · <꼬리표>`. 이름은 저장하지 않는다(`firmware.prototype`의 `summary`가 복사된 값이라 믿을 수 없다).
- **ArduPilot**: `GET https://firmware.ardupilot.org/manifest.json.gz`, 작업 스레드에서 `gunzip`과 해석. 기체 콤보 `Copter, Heli, Plane, Rover, Sub`, 버전 콤보는 `OFFICIAL`(`<버전> (안정판)`) 다음 `STABLE-x.y.z` 최신 순. 조건: `format == apj`, `board_id` 일치(보드 255는 9로 본다), Heli는 `mav-type == HELICOPTER`, Copter는 그 반대. 후보 표시는 `platform`. 86MB를 한 번에 `QJsonDocument`로 만들지 않고 항목 단위로 잘라 맞는 것만 해석한다(순수 함수 `scanManifest(bytes, boardId)`). 결과는 앱이 켜져 있는 동안 메모리에 둔다.
- **파일 선택**: `FileField` + 시스템 파일 대화상자, `.px4`·`.apj`. 고르면 바로 해석하고 호환을 본다.
- 후보 규칙은 순수 함수 `pickCandidate(count) -> {None, Auto, Choose}`. 하나면 선택해 둔다. 여럿이면 선택 없음. 없으면 `Banner` "공식 목록에 이 보드용 펌웨어가 없어요. 파일을 직접 골라요."
- 목록을 못 받으면 `Banner` "목록을 받지 못했어요. 인터넷을 확인하거나 파일을 직접 골라요."
- 하단: `취소하고 FC 부팅`(`bootAndReset`), `다음`(선택이 있을 때만).

### 6.6 파일과 호환 판정 (`FirmwareImage`, 순수)
- JSON을 읽어 `magic`이 `APJFWv1`이면 ArduPilot, `PX4FWv1`이면 PX4. 그 밖은 `BadImage`.
- `image`, `extf_image`는 base64 + zlib. `extf_*` 키가 없으면 0. 풀린 길이가 `image_size`, `extf_image_size`와 다르면 `BadImage`.
- `compatible(boardId, fileBoardId)`: 같으면 참. 보드 255와 파일 9, 보드 9와 파일 255는 같은 계열이므로 참(조사 §Q5). 그 밖은 거짓이고 굽지 않는다(`WrongBoard`). 선택할 때와 내려받은 뒤 두 번 본다.
- `image_size`가 플래시 크기를 넘으면 `TooLarge`.
- 비교 버전 `expectedVersion`: PX4 공식은 태그, ArduPilot 공식은 목록의 `mav-firmware-version-major/minor/patch`, PX4 파일은 `git_identity`의 `\d+\.\d+\.\d+`, ArduPilot 파일은 없음(`.apj`에 사람이 쓴 버전이 없다).

### 6.7 3단계: 확인
`KeyValueRow`: `FC 이름`(USB 제조사·제품), `올릴 펌웨어`(종류, `expectedVersion`, 보드: 공식은 후보 표시, 파일은 `summary`), `출처`(`PX4 공식`·`ArduPilot 공식`·`내 PC 파일`). `뒤로`, `HoldToConfirm`(`길게 눌러 굽기`).

### 6.8 4단계: 굽기와 확인
1. `Job(OperationKind::FcFlash)`을 만든다. `JobView`(`showError: false`)와 `StepList`(내려받기·지우기·쓰기·검증·재부팅·재연결)를 보여 준다. 파일이면 내려받기 행은 없다.
2. 내려받기(`Paths::cacheFirmware()`로, 공식 출처만) → 해석 → 호환 판정. 끝나면 앞의 파일을 지운다.
3. 지우기 → (외부) → 쓰기 → 검증. `cancellable`은 지우기 시작 전까지만 참이다. 취소하면 `finishCancelled`, `Phase::Ready`, `Step::Confirm`, 임대 유지.
4. 검증 성공이면 Job `succeed`, `boot()`, 포트를 닫고, `portClosed` 뒤 임대를 놓고 `Reconnecting`.
5. 실패하면 Job `fail`, `Failed`. 포트가 살아 있으면 `canRetry`이고 문구는 "%1에 실패했어요. FC는 부트로더에서 기다리고 있어요."(`%1`은 지우기·쓰기·검증) 와 `다시 굽기`, `처음으로`. `다시 굽기`는 내려받기 없이 `sync` + `identify`부터 한다. `처음으로`는 부팅 없이 포트를 닫는다(FC는 부트로더에 남고 전원을 다시 넣으면 된다). 포트를 잃으면 "포트를 잃었어요. USB를 다시 꽂고 처음부터 해요."
6. `Reconnecting`: 기준 목록은 `boot()` 시점의 `known2`. `kReconnectWait` 60초 동안 500ms마다 `refreshPorts()`. 앱 모드 포트는 ① 처음 고른 포트 이름이 있으면 그 포트(사라졌다 돌아온 뒤, 또는 `boot()` 뒤 3초가 지나도 사라지지 않았으면 그대로), ② 없으면 `known2`에 없던 새 포트. 후보가 둘 이상이거나 다른 링크가 이미 열려 있으면 재연결하지 않고 `NoReturn`.
7. 115200으로 `connectLink`. 열기가 실패하면 500ms 뒤 다시, 60초까지. 기체가 나타나면 `kVersionWait` 5초 동안 `firmwareVersion`을 기다린다.
8. 판정: 종류(`firmwareName`)가 다르면 항상 `Mismatch`. 종류가 같고 버전을 둘 다 알면 비교해 `Done` 또는 `Mismatch`. 어느 쪽이든 모르면 `Done`. 문구는 `Done` "<종류> <버전>으로 올라갔어요"(버전을 모르면 "<종류>로 올라갔어요"), `Mismatch` "올린 펌웨어와 달라요: <종류> <기체 버전>".
9. 시간이 넘으면 `NoReturn` "굽기는 끝났지만 FC가 돌아오지 않았어요. 포트를 골라 직접 연결해요."
10. 끝나면 `처음으로`. 연결은 유지한다.

### 6.9 그 밖
- 스레드: `FlashWorker`(QObject, 자기 `QThread`)가 `RawPort`와 `Bootloader`를 쥔다. 결과는 큐드 시그널. 취소·중단은 원자 값. 후보 포트의 `sync`도 워커에서 하고 GUI 스레드는 막지 않는다.
- `~FcFlashService`는 중단 플래그를 세우고 스레드를 `wait`한다. 앱 종료는 막지 않는다.
- 서비스의 대기는 `Timeout`, 값은 `Constants.h`(`kHeartbeatWait`, `kRebootWait`, `kBootloaderWait`, `kReconnectWait`, `kVersionWait`, `kScanPeriod`).
- 사건은 `KGC_LOG_*`(`FcFlashEvent`)에 남긴다. 단계 시작, 보드 정보, 파일 이름, 결과.
- `FcFlashController`는 형이 있는 QML 싱글턴(`Kgc.FcFlash`). 문구는 QML이 만들고 실패 글자는 `Q_INVOKABLE failureText()`를 `{ translator.language; … }` 방식으로 읽는다(`WrongBoard`의 두 값은 서비스가 들고 있다). 패널은 `registerUi`가 `PanelRegistry`에 id `fcFlash`, 순서 1, 그룹 1로 등록한다. 1단계 포트 콤보의 목록은 `LinkManager::ports()`.
