## 6. 동작

### 6.1 생성과 자동 받기
`Composition`이 `VehicleRegistry::vehicleAdded`에서 `new ParamService(*vehicle, *policy, *http, vehicle)`를 만든다. 첫 HEARTBEAT로 생긴 뒤 곧바로 `refresh()`를 부른다. 이때 `states()->arming().armed`면 보내지 않고 `SkippedArmed`가 된다. 사용자가 새로고침을 누르면 시동 중이어도 받는다(`OperationKind::Read`는 Allow).
기체 링크가 끊겼다 돌아올 때(`link().lost`가 참→거짓) 상태가 `Incomplete`이거나 `reboot()`를 보낸 뒤면 `refresh()`를 다시 부른다.

### 6.2 내려받기 (`Job`, `OperationKind::Read`, 단계 키 `"내려받기"`, 취소 가능)
1. 받은 표를 지우지 않는다. 이번 회차의 받은 번호 집합만 비운다. `PARAM_REQUEST_LIST`를 `OutboundKind::Param`으로 보낸다.
2. `PARAM_VALUE`: 이름은 16바이트, 널 없을 수 있음. `_HASH_CHECK`는 버린다. `decodeParam`으로 값을 풀어 표를 갱신하거나 추가한다(대기값은 그대로). `param_index`가 65535면 번호 집합에 넣지 않는다. 아니면 넣고 `param_count`를 total로 삼는다.
3. 진행률은 받은 수 / total. PARAM_VALUE가 올 때마다 `kParamGapWait`(1초) `Timeout`을 다시 건다.
4. 첫 PARAM_VALUE 전에는 `kParamListTimeout`(5초)마다 목록 요청을 다시 보내고, `kParamListRetries`(4회)를 넘기면 실패(`ParamError::Timeout`).
5. 받은 수가 total이면 완료: 내려받지 못한 표 행이 있으면 지우고(번호 집합의 이름으로 판단, 대기값도 함께), `Complete`.
6. 1초간 새 값이 없으면 `nextRequests`: 번호 0부터 안 받은 것 중 `tries < kParamReadTries`(5)인 것을 최대 `kParamReadBatch`(10)개 고르고 tries를 올려 돌려준다. 각각 `PARAM_REQUEST_READ`(`param_index`=번호, id 비움)를 보내고 다시 1초를 건다. 고른 것이 없고 빠진 번호가 남았으면 실패(`ParamError::Incomplete`), `Incomplete`. 받은 값은 표에 남긴다.
7. 내려받는 중이 아닐 때 온 PARAM_VALUE도 값을 갱신한다. 표에 없는 이름이면 추가한다.
8. Job이 끝나면 `Job::finished` 뒤 `job()`은 nullptr.

### 6.3 메타데이터
`capabilitiesChanged`로 `vehicleType`과 `firmwareVersion`이 둘 다 찼을 때 한 번 시작한다. 플러그인의 `paramMetadataSource`:
- px4: `Flat`, urls `https://px4-travis.s3.amazonaws.com/Firmware/v<major.minor.patch>/_general/parameters.json`, 이어서 `.../Firmware/stable/_general/parameters.json`. cacheName `PX4-<major.minor.patch>`.
- ardupilot: `MAV_TYPE`을 Copter(쿼드·헥사·옥타·트라이·동축·헬기·도데카·데카, 프레임 미설정 `MAV_TYPE_GENERIC`), Plane(고정익, VTOL 계열), Rover(지상 차량, 수상), Sub(잠수함), Tracker(안테나 트래커)로 고른다. 그 밖이면 `None`. urls는 `https://raw.githubusercontent.com/ArduPilot/ParameterRepository/main/<Type>-<major>.<minor>/apm.pdef.json`을 minor, minor−1, minor−2 순서(0 아래로 안 감). `Grouped`, cacheName `<Type>-<major>.<minor>`.

순서: `Paths::cacheMetadata()/params-<cacheName>.json`이 있고 파싱 결과가 비어 있지 않으면 그것을 쓴다 → 없으면 urls를 차례로 `Http::download`, 첫 성공을 그 경로에 두고 파싱한다 → 전부 실패하거나 결과가 비면 `Failed`. 이름·값 표는 메타데이터 없이도 동작한다.
파싱 규칙:
- Flat: `parameters[]`의 `name shortDesc longDesc units min max default group rebootRequired`, `values[]{value,description}`, `bitmask[]{index,description}`.
- Grouped: 최상위 키 `json`은 건너뛴다. 나머지 최상위 키가 `group`, 그 안의 키가 이름. `DisplayName`→title, `Description`→description, `Units`, `Range{low,high}`(문자열 숫자), `Values{"값":"이름"}`(값은 실수일 수 있음, 값 순서로 정렬), `Bitmask{"비트":"이름"}`, `RebootRequired`·`ReadOnly`는 문자열 `"True"`일 때 참. 기본값은 없다.
Params는 메타데이터가 들어오면 각 행 `group`을 다시 계산하고 `dataChanged`를 낸다. 행 묶음 계산: `plugin.paramGroup(name, meta.group)` 전체를 모아 `mergeSingleGroups`.

### 6.4 값 처리
- 값은 `double`로 들고 형은 FC가 보낸 `param_type`을 그대로 쓴다.
- `Bytewise`: 실수형은 float 그대로, 정수형은 float 비트를 그 형으로 읽는다. `CCast`: float를 숫자로 그대로 쓴다.
- `formatValue`: 정수형은 정수 표기, `REAL32`는 float 왕복 최단 고정소수 표기(`std::to_chars`, `std::chars_format::fixed`), `0.1`은 `0.1`, `100000`은 `100000`.
- `sameValue`: 정수형은 같음, 실수형은 `float` 변환 뒤 2 ULP 안(`kParamFloatUlps`). 상대 오차 비교는 쓰지 않는다(1013.25와 1013.26을 같다고 본다).
- `parseValue`: 앞뒤 공백 제거, `,`→`.`, 숫자가 아니거나 무한대면 `NotANumber`. 정수형에 소수면 `NotInteger`, 형의 범위 밖이면 `TypeLimit`.
- `setPending`: 이름 없음 `NotFound`, 읽기 전용 `ReadOnly`. 값이 FC 값과 `sameValue`면 대기값을 지운다. 범위 검사는 서비스가 하지 않는다(화면이 §6.8대로 묻는다).
- 새 PARAM_VALUE가 대기값과 `sameValue`면 그 대기값은 지운다.

### 6.5 쓰기 전
`writeDecision`: 대기값 1개면 `ParamSingle`, 2개 이상이면 `ParamBulk`로 `ArmedPolicy::check(kind, VehicleScope::One(vehicle))`.

### 6.6 쓰기 (`writePending`, `Job`, 같은 kind, 단계 키 `"값 쓰기"`, 영어 "Write values", 취소 가능)
1. Job이 이미 있으면 아무 일도 안 한다. 대기값 0개면 `writeFinished(0, {})`.
2. `Paths::paramsBackups()/<sysid>-<yyyyMMdd-HHmmss>.params`에 전체 FC 값을 쓴다. 실패하면 Job 실패(`BackupFailed`), 아무것도 보내지 않는다.
3. 대기값을 이름순으로 하나씩: `Bulk`이고 지금 시동 중이면 멈추고 Job 실패(`Armed`). `PARAM_SET`(`OutboundKind::Param`, `encodeParam`, 저장된 type)을 보내고 같은 이름의 PARAM_VALUE를 `kParamSetTimeout`(1초) 기다린다. `kParamSetRetries`(2회) 다시 보낸다.
4. 돌아온 값이 `sameValue`면 성공: 표 값 갱신, 대기값 지움, 메타데이터 `rebootRequired`면 `rebootNeeded` 참. 아니면 다음 시도로 간다. 시도를 다 쓰면 실패 목록에 넣고 대기값은 남긴다(표 값은 마지막으로 돌아온 값).
5. 취소는 지금 줄의 응답을 처리한 뒤 멈춘다.
6. 끝나면 `writeFinished(성공 수, 실패 이름)`. 실패가 있어도 Job은 성공, 취소면 `finishCancelled`.

### 6.7 재부팅과 파일
- `reboot()`: `ArmedPolicy::check(ParamBulk, One)`이 Deny면 `rebootFinished(Armed)`. `CommandQueue::send`로 `MAV_CMD_PREFLIGHT_REBOOT_SHUTDOWN` param1=1, `{.retries = 0}`. ACK가 accepted면 `rebootNeeded` 거짓, 성공 알림. ACK가 거부면 `RebootRefused`. 응답 없음(`Timeout`)도 성공으로 본다(바로 끊기는 FC가 있다).
- `saveFile`: §형식대로 쓴다. `QSaveFile`. 실패는 `FileWrite`.
- `compareFile`: 파일을 파싱해 이름마다 `paramFileSkip`에 있으면 skipped, FC에 없으면 missing, 읽기 전용이면 readOnly, `sameValue`면 same, 나머지는 changed(자연순).
- `applyFile(names, diff)`: 고른 이름을 `setPending`한다. 쓰기는 사용자가 `값 쓰기`를 눌러야 한다.
- 재연결로 새 `Vehicle`이 생기면 새 서비스가 자동으로 받는다.

- 거름은 AND: 묶음, 검색어(공백으로 나눈 낱말 전부가 이름·title·description 중 하나에 대소문자 무시 포함), 토글. `ParamsFilterModel`(`QSortFilterProxyModel`).
- 가운데 `ParamTable`: `ListView` 가상화 표. 열 이름, 값, 기본값(`hasDefaults`일 때만), 단위, 범위·선택지, 설명. 행 높이 고정. 설명은 말줄임. 값 칸은 `valueText` 또는 `pendingText`; 선택지 있는 값은 라벨로 보여 준다. 대기값 칸은 `okSoft` 바탕에 `ok` 글자. `rebootRequired`인 행은 값 옆에 `refresh` 아이콘(`warn`).
- 범위·선택지 칸: 선택지면 `값 라벨, …`, 비트면 `비트 n개`, 범위면 `min ~ max`, 한쪽만 있으면 `min 이상`·`max 이하`.
- 행을 고르면 값 칸이 편집기가 된다: `number`는 `TextBox`, `option`은 `ComboField`(목록에 없는 값이면 맨 앞에 숫자 항목), `bitmask`는 `TextBox` + 작은 단추 `비트 고르기`. 읽기 전용은 글자만. Enter·초점 이동은 확정, Esc는 취소.
- 확정: `parseValue` 실패면 값 칸 아래 오류 글(`danger`)이 뜨고 대기값을 바꾸지 않는다. 범위 밖이면 `ConfirmDialog`(제목 "범위를 벗어났어요", 글 "<이름>의 범위는 <범위>예요. 이 값으로 둘까요?"). 예면 `setPending`, 아니오면 이전 값.
- 고른 행 아래 `ParamDetail`: 이름, `FC 값 x` + 대기값 있으면 `새 값 y`, 긴 설명, 단추 `기본값으로`(기본값 있고 FC 값·대기값과 다를 때), `되돌리기`(대기값 있을 때). 기본값으로는 `setPending(default)`.
- 오른쪽 `ParamActions`(세로): `값 쓰기 (n)`(주 단추, n=0이면 비활성), `새로고침`, `파일 불러오기`, `파일로 저장`, `FC 재부팅`. Job이 도는 동안 전부 비활성. `Ctrl+S`는 `값 쓰기`와 같다.
- `값 쓰기`: `writeDecision` Deny면 토스트 "시동 중에는 쓸 수 없어요". 아니면 `WriteConfirmDialog`: 제목 "값 n개를 쓸까요?", 표(이름·지금·새 값), 글 "쓰기 전에 전체 값을 백업해요." AllowWithWarning이면 확인 단추가 `HoldToConfirm`.
- `파일 불러오기`: 파일 대화상자(`.params .param .parm`) → `FileCompareDialog`: 제목 "파일과 FC 비교", 줄 "바뀌는 값 n · 같은 값 n · FC에 없음 n · 읽기 전용 n · 건너뜀 n", 표(체크·이름·FC 값·파일 값, 전부 체크), 단추 `고른 값 올리기`, `취소`. 바뀌는 값이 0이면 `고른 값 올리기` 비활성. `badLines`나 `otherComponent`가 있으면 "읽지 못한 줄 n"을 줄에 더한다.
- `파일로 저장`: 저장 대화상자, 기본 이름 `<firmwareName>-<sysid>.params`, 기본 폴더 `Paths::paramsBackups()`.
- `FC 재부팅`: `ConfirmDialog` 제목 "FC를 재부팅할까요?" 뒤 `reboot()`.
- `BitmaskDialog`: 비트마다 `CheckRow`. 새 값은 지금 값에서 목록에 있는 비트만 바꾼 것(목록에 없는 비트는 그대로), 값의 형 폭 안에서 계산한다(INT32 비트 31 포함). 확인하면 §확정 흐름.
- 위쪽 배너: `Downloading`이면 `JobView`, 쓰기 중에도 `JobView`. `Incomplete`면 `Banner`(warn) "FC가 파라미터를 다 보내지 않았어요 (받은 수/전체)". `SkippedArmed`면 `Banner` "시동 중이라 파라미터를 받지 않았어요. 새로고침을 누르면 받아요." `rebootNeeded`면 `Banner`(warn) "재부팅해야 적용되는 값이 있어요". `metadataState == Failed`면 위 줄에 작은 글 "설명을 받지 못했어요".
- 쓰기가 끝나면 토스트: 실패 없음 "n개를 썼어요", 있으면 "n개를 썼어요. m개는 쓰지 못했어요: 이름들"(앞 3개, 넘으면 "외 k개").
- `hasDefaults`: 메타데이터에 기본값이 하나라도 있으면 참. `isDefault`: 기본값이 있고 FC 값과 `sameValue`.
- `기본값과 다른 값`: 기본값이 있고 다른 행만.
- 색·크기는 `Theme` 토큰만. 새 크기 토큰 `paramGroupWidth`(190)·`paramActionsWidth`(130)·`paramRowHeight`(30)·`paramNameWidth`(220)·`paramValueWidth`(130)·`paramDefaultWidth`(100)·`paramUnitWidth`(56)·`paramRangeWidth`(190), 남는 폭은 설명.

### 6.8-1 빈칸 메움 (builder check, 앞 절과 다르면 이 절이 맞다)
1. **자동과 수동**: 공개 `refresh()`는 언제나 받는다(Job이 있으면 아무 일도 안 함). 생성자 끝과 링크 복귀 때는 비공개 `autoRefresh()`: 시동 중이면 `SkippedArmed`, Job이 있으면 그 Job이 끝날 때 다시 판단한다. `Composition`은 만들기만 한다.
2. **상태**: Timeout 실패는 `Incomplete`, 취소는 `Idle`. "첫 PARAM_VALUE"는 `param_index`≠65535인 첫 값. 완료 판정은 total>0일 때만. `Incomplete`면 표의 대기값과 행을 지우지 않는다.
3. **Job 실패 표시**: 컨트롤러가 `jobChanged`에서 `Job::finished`에 이어, 실패면 토스트로 `errorText`(취소는 없음). `writeFinished`는 `Armed` 중단과 취소 때도 그때까지의 수로 내고, `BackupFailed`에서는 내지 않는다.
4. **Busy**: `reboot()`은 Job이 있으면 `rebootFinished(Busy)`. `refresh()`는 1번대로.
5. **개수**: `ParamService::receivedCount()`, `totalCount()`를 더한다.
6. **재부팅 결과**: Accepted와 Timeout은 성공(`rebootNeeded` 거짓, 토스트 "재부팅을 보냈어요"). 거부 ACK와 NoLink는 `RebootRefused`. Gone은 아무것도 안 한다.
7. **화면 오류**: `saveFile`·`compareFile`·`setPending` 실패는 토스트로 `errorText`. 저장 성공 토스트 "파일로 저장했어요".
8. **파일 값 검사**: `compareFile`은 각 값을 그 파라미터 형으로 `validateForType(double, type)`(정수형 소수, 형 범위 밖이면 오류, `parseValue`도 이 함수를 쓴다)로 검사해 걸리면 `badLines`에 센다. `changed`에 들어가지 않는다.
9. **이름들**: `struct ParamFileHeader { int sysid; QString firmwareName; int vehicleType; QString firmwareVersion; }`, `# Vehicle:` 줄은 정수 그대로. `struct ParsedParamFile { QList<QPair<QString,double>> entries; int badLines; int otherComponent; }`. `internal/Params.cpp`를 더한다. `ParamStates.h`는 `FlashStates.h`처럼 `Q_NAMESPACE`·`QML_NAMED_ELEMENT(ParamStates)`·`Q_ENUM_NS`.
10. **송신 실패·기체 제거**: 송신 실패는 응답 없음과 같게 다룬다. 타이머가 울릴 때 `sender()`가 nullptr면 타이머를 멈추고 Job을 `fail(Timeout)`, `writeFinished`는 내지 않는다.
11. **행과 상세**: 표 행의 편집기는 행 높이에 맞춘다(`paramRowHeight` 34). 오류 글과 `ParamDetail`은 `ListView` 아래 고정 영역 한 곳에 둔다. `TextBox`의 `errorText`는 표 안에서 쓰지 않는다.
12. **더 고칠 곳**: `resources/icons/icons.txt`에 `refresh`, `src/main/CMakeLists.txt`의 `SOURCE_TARGETS`에 `kgc_params`·`kgc_vehicle_firmware`, `.github/workflows/linux.yml` qmllint 줄, 루트 `CMakeLists.txt` 기능 목록.
13. **토스트**: `app/notify`는 아직 없다. `ParamsPanel` 안에 `Toast` 하나와 `TimerBox`, 표시 시간 토큰 `paramToastMs`(4000). `Notify`로 옮기는 일은 `notify` 모듈 버전에서 한다. 시안과 §6.8이 다르면 §6.8이 맞다(결과 창 없음, 배너의 재부팅 글자는 단추 아님).
14. **묶음 계산**: 새 행은 `paramGroup` 값을 그대로 받는다. `mergeSingleGroups`는 내려받기 끝, 메타데이터 도착, 내려받기 밖에서 행이 늘 때만 전체 실행한다.
15. **표시 역할**: `valueText`·`pendingText`는 숫자 표기. `optionText`는 보이는 값(대기값이 있으면 대기값)의 선택지 라벨, 없으면 빈 문자열. 값 칸은 `optionText`가 있으면 그것. `rangeText`는 범위·선택지 칸 전체 글. 표의 설명 열은 `title`, 비면 `description`. 쓰기 확인 창은 숫자. `Params`는 `Translator` 언어가 바뀌면 `rangeText` 역할의 `dataChanged`를 낸다.

### 6.8-2 재부팅 뒤 다시 잇기 (F4 시험 결과로 추가)
USB FC는 재부팅하면 포트가 사라져 `linkFailed`로 끝나고 기체가 지워진다. 앱이 보낸 재부팅이면 스스로 다시 연다.
- 모듈은 혼합이 된다: 전역 `ParamRebootReconnect`(`api/kgc/params/`), 기체별 `ParamService`. `Composition`이 하나 만들어 `ParamService`에 참조로 넘긴다.
- `ParamRebootReconnect(LinkManager&, VehicleRegistry&, QObject* parent)`, `void watch(const LinkConfig& config)`: 재부팅이 성공으로 판정될 때 `ParamService`가 `vehicle.linkConfig()`로 부른다. `kRebootReconnectWait`(30초) 창을 연다.
- 창 안에서 `linkClosed`(오류 있음) 또는 `linkFailed`가 나면 `kRebootOpenDelay`(6초) 뒤 `connectLink(config)`를 시도한다. 실패하거나 다시 닫히면 `kRebootRetry`(1초) 뒤 다시 시도한다.
- `vehicleAdded`, 사용자의 연결 끊기(`linkClosed` 오류 없음), 창 끝에서 감시를 마친다. 창이 끝나도 기체가 없으면 그대로 둔다(사용자가 연결).
- UDP처럼 링크가 안 닫히면 할 일이 없다. 다시 받기는 §6.1의 링크 복귀가 맡는다.
- 새 `Vehicle`이 생기면 새 `ParamService`가 자동으로 받는다.
- 로그 `ParamEvent::RebootReconnect`.

### 6.8-3 시리얼 쓰기의 잠깐 바쁨 (F5 시험 결과로 추가)
Qt는 쓰기의 `EAGAIN`도 `ResourceError`로 알린다. 실제 FC에서 연결 직후 약 6번에 1번 이것으로 링크가 닫혔다. `comm/links/serial`의 `serialErrorClosesLink`는 `ResourceError`의 글이 `qt_error_string(EAGAIN)`과 같으면 닫지 않고, 처리기가 `clearError()` 한다. 나머지 오류는 그대로 닫는다. 닫을 때는 `SerialPortLost` 로그에 오류 번호와 글을 남긴다.
