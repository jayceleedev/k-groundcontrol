## 1. 목적
좌 메뉴 **시뮬레이션**에서 ArduPilot SITL을 골라 내려받고, 이 PC에서 실행해 앱이 바로 붙는다. FC 없이 설정·파라미터·비행 화면을 시험할 수 있다.

## 2. 사용자 결정 (2026-11-03)
1. Windows와 Linux(x86_64) 둘 다. 기체 4종(멀티콥터·헬리콥터·비행기·로버), 배포판 3종(안정판·베타·최신).
2. 기본 파라미터, 홈 위치, 속도 배수, 값 초기화, 시작·정지, 자동 연결, 앱을 끄면 SITL도 끈다.
3. 뒤로 미룸: PX4 SITL, 여러 대 동시 실행, 지도에서 홈 고르기, 추가 명령줄.
4. 좌 메뉴 자리: `펌웨어 세팅` 바로 아래, 같은 묶음.
5. 기본 홈: 부산 해운대 해수욕장 35.158700, 129.160400, 고도 3 m, 기수 0°. 마지막으로 쓴 값을 기억한다.

## 6. 동작

### 6.1 상태
- `Idle`: 실행 중이 아님. `Downloading`: Job이 돈다. `Starting`: 프로세스를 띄웠고 링크가 열리기를 기다린다. `Running`: 프로세스가 살아 있고 링크가 한 번 열렸다. `Failed`: 마지막 시도가 실패(`lastError`). `Failed`에서 `start`·`redownload`는 다시 할 수 있다.
- `Downloading`·`Starting`·`Running` 중의 `start`·`redownload`는 `Busy`.
- 플랫폼은 `SitlService.cpp` 한 곳에서 `Q_OS_WIN`이면 `Windows`, 아니면 `Linux`로 정한다.

### 6.2 내려받을 파일 (`sitlFiles`)
상수는 `internal/Constants.h`.
- **Windows**: 바탕 `https://firmware.ardupilot.org/Tools/MissionPlanner/sitl/` + 폴더. 안정판은 Copter·Heli → `CopterStable/`, Plane → `PlaneStable/`, Rover → `RoverStable/`. 베타 → `Beta/`. 최신 → 바탕 그대로. 실행 파일 원본 `ArduCopter.elf`·`ArduHeli.elf`·`ArduPlane.elf`·`ArduRover.elf`를 `ArduCopter.exe` 꼴(확장자만 `.exe`)로 저장. 같은 폴더의 DLL 10개를 같은 이름으로: `cygatomic-1.dll cyggcc_s-1.dll cyggcc_s-seh-1.dll cyggomp-1.dll cygiconv-2.dll cygintl-8.dll cygquadmath-0.dll cygssp-0.dll cygstdc++-6.dll cygwin1.dll`. 주소의 `+`는 `%2B`로 쓴다.
- **Linux**: `https://firmware.ardupilot.org/<Copter|Plane|Rover>/<stable|beta|latest>/<폴더>/<파일>`. Copter `SITL_x86_64_linux_gnu/arducopter`, Heli `Copter/…/SITL_x86_64_linux_gnu-heli/arducopter-heli`, Plane `SITL_x86_64_linux_gnu/arduplane`, Rover `SITL_x86_64_linux_gnu/ardurover`. 받은 뒤 실행 권한(소유자 rwx, 그룹·기타 rx).
- **기본 파라미터**(둘 다, 마지막 항목, 저장 이름 `defaults.parm`): `https://raw.githubusercontent.com/ArduPilot/ardupilot/master/Tools/autotest/` + Copter `default_params/copter.parm`, Heli `default_params/copter-heli.parm`, Plane `models/plane.parm`, Rover `default_params/rover.parm`.

### 6.3 명령줄 (`sitlArguments`)
`--model <sitlModel> --home <위도>,<경도>,<고도>,<기수> --speedup <n> -I0 --serial0 udpclient:127.0.0.1:<kUdpPort> --defaults defaults.parm` 그리고 `wipe`면 끝에 `--wipe`. 위도·경도는 소수 7자리, 고도는 소수 1자리, 기수는 정수, 소수점은 언제나 `.`(시스템 언어와 무관). 각 값은 별도 인자다(따옴표 없음).

### 6.4 시작 (`start`)
1. `Busy` 판정, `checkHome`이 비지 않으면 `BadHome`, `speedup`이 생성된 Min~Max 밖이면 `BadHome`(화면이 먼저 막는다). `LinkManager::linkId() >= 0`이면 `LinkBusy`로 즉시 반환(상태 그대로). 통과하면 설정 저장.
2. `cached`가 아니면 `Downloading`, `SitlDownload` 시작. 실패면 `Failed`(`DownloadFailed`), 취소면 `Idle`. 성공하면 다음 단계.
3. 실행 폴더 `Paths::sitl()/<sitlRunFolderName>/`를 만들고 캐시의 `defaults.parm`을 덮어 복사한다. 출력 줄을 비운다.
4. `Starting`. `Simulator::start(캐시의 실행 파일 절대 경로, sitlArguments, 실행 폴더)`. `failedToStart`면 `Failed`(`StartFailed`).
5. `started`에서 `LinkManager::connectLink({Udp})`. 바로 실패하면(`AlreadyConnected`) 프로세스를 멈추고 `Failed`(`LinkBusy`). 접수되면 이 링크 번호를 기억하고 `linkOpened`를 기다린다. `linkOpened`면 `Running`, `linkOpenedBySitl` 참. `linkFailed`(예: `UdpBindFailed`, 다른 프로그램이 14550을 씀)면 프로세스를 멈추고 `Failed`(`LinkFailed`). `Starting` 중의 `stop()`은 링크 요청과 프로세스를 함께 멈춘다.

### 6.5 실행 중
- `LinkManager::linkClosed`가 이 서비스가 연 링크 번호로 오면 `linkOpenedBySitl` 거짓. 프로세스는 그대로 둔다. `reconnect()`는 `linkId() < 0`일 때만 5단계의 연결을 다시 한다(아니면 `LinkBusy`).
- `Running` 중에 다른 곳(상단 연결 단추)이 UDP 링크를 열면(`linkOpened`이고 `linkConfig().kind == Udp`) 그 링크도 이 서비스의 것으로 본다(`linkOpenedBySitl` 참).
- 출력 줄은 마지막 `kSitlOutputLines`(200)줄만 기억한다. 줄 끝의 `\r`은 지운다. 화면 갱신은 `outputChanged`를 `kSitlOutputThrottle`(200 ms) `Timeout`으로 묶어 낸다.
- 요청하지 않은 종료(`exited(code, crashed, false)`, `Starting` 중이어도): 이 서비스가 연 링크가 열려 있으면 끊고 `Failed`(`Crashed`). `lastExitCode`는 `crashed`면 −1, 아니면 `code`.

### 6.6 정지 (`stop`)와 앱 종료
- `stop()`: `Downloading`이면 Job 취소. `Starting`·`Running`이면 이 서비스가 연 링크가 열려 있거나 열리는 중일 때만 `disconnectLink()`, 그다음 `Simulator::stop()`, `Idle`. 다른 상태면 아무 일도 없다.
- `QCoreApplication::aboutToQuit`에서 `stop()`. 서비스 소멸자는 `LinkManager`를 부르지 않고 프로세스만 멈춘다(`Simulator` 소멸자). 앱이 끝난 뒤 SITL 프로세스가 남지 않는다.

### 6.7 다시 받기 (`redownload`)
`Running`·`Downloading`이면 `Busy`. 아니면 §6.4 2단계의 내려받기만 한다(캐시가 있어도). 끝나면 `Idle` 또는 `Failed`, `cacheChanged`.

### 6.8 화면 (`specs/ui/sitl.html`)
- 위: 제목 "시뮬레이션", 작은 글 "ArduPilot SITL을 내려받아 이 PC에서 실행해요."
- **기체**: `ChoiceCard` 4개 가로(멀티콥터 `drone`, 헬리콥터 `helicopter`, 비행기 `plane`, 로버 `car`).
- **배포판**: `PillGroup` 하나(안정판 / 베타 / 최신 개발판).
- **홈 위치**: 위도·경도·고도(m)·기수(°) 입력 4칸, 옆에 작은 단추 "해운대로 되돌리기"(설정 기본값으로 채움). "해운대로 되돌리기"는 생성된 `<name>Default()` 네 개로 채운다. `checkHome`이 돌려준 칸마다 그 칸 아래 빨간 글 `errorText(BadHome)`, 하나라도 있으면 시작 단추 비활성. 입력 칸은 `NumberBox`.
- **속도 배수** 1~10 숫자 상자, **값 초기화** 체크 상자 "저장된 파라미터를 지우고 시작"(작은 글 "기본 파라미터로 처음부터 시작해요").
- `Downloading`·`Starting`·`Running` 중에는 위 입력이 모두 비활성.
- **상태 카드**: 상태 칩(멈춤 / 받는 중 / 시작하는 중 / 실행 중 / 멈췄어요), 캐시 글 "받은 파일: 2026-11-03 14:20" 또는 "처음 시작하면 파일을 내려받아요 (약 15 MB)". 실행 중이면 "UDP 14550으로 연결했어요" 또는 링크가 닫혔을 때 "연결이 끊겼어요" + 단추 "다시 연결". 내려받는 중이면 `JobView`(취소 가능, 단계 글은 Job의 단계 이름 그대로), 이때 시작·다시 받기 단추는 숨긴다. `Failed`면 닫기 없는 `Banner`(warn) `errorText(lastError)`, `Crashed`이고 `lastExitCode >= 0`이면 뒤에 " (종료 코드 N)"(문구 "종료 코드 %1").
- 단추: 주 단추 "시작"(실행 중이면 "정지"), 보조 단추 "다시 받기"(실행·내려받기 중 비활성).
- `linkBusy`이고 `Idle`·`Failed`면 닫기 없는 `Banner`(info) "다른 연결이 열려 있어요. 연결을 끊은 뒤 시작할 수 있어요."와 시작 비활성.
- **출력**: 읽기 전용 `TextArea`를 `ScrollView`에 넣은 고정폭 글꼴 상자(높이 약 10줄, 새 줄이 오면 맨 아래로, 색은 기존 바탕·글자 토큰, 고정폭 글꼴 토큰이 없으면 `Theme.monoFamily`를 더한다), 제목 "시뮬레이터 출력". 비어 있으면 "시작하면 여기에 시뮬레이터 출력이 보여요."
- 크기·색은 `Theme` 토큰. 새 토큰이 필요하면 `Theme.qml`·`themes/`에 더한다.
- objectName(테스터용): `sitlPanel`, `sitlVehicle_<copter|heli|plane|rover>`, `sitlRelease`, `sitlHomeLatitude`·`sitlHomeLongitude`·`sitlHomeAltitude`·`sitlHomeHeading`, `sitlHomeReset`, `sitlSpeedup`, `sitlWipe`, `sitlStart`(시작·정지 겸용), `sitlRedownload`, `sitlReconnect`, `sitlStateChip`, `sitlCacheText`, `sitlBanner`, `sitlLinkBusy`, `sitlJob`, `sitlOutput`.

### 앱 (Linux, PM 테스터, 실제 인터넷)
- T5 좌 메뉴 두 번째가 "시뮬레이션", 그 뒤 구분선, 나머지 메뉴 순서는 그대로.
- T6 처음 시작: 내려받기 JobView 진행 → 실행 → 내려받기가 끝난 뒤 30초 안에 기체 연결, 기체의 위치가 기본 홈에서 0.001° 안.
- T7 두 번째 시작: 내려받기 없이(로그에 `SitlDownloadStarted` 없음) 10초 안에 연결.
- T8 정지: 링크 닫힘, SITL 프로세스 없음(`pgrep`), 상태 멈춤.
- T9 기체 4종: 각각 시작해 HEARTBEAT 기체 종류가 맞음(멀티콥터 2, 헬리 4, 비행기 1, 로버 10), 0.3.0 수동 기체 설정에서 `FRAME_CLASS`가 0이 아님(Copter·Heli).
- T10 배포판: 베타·최신이 다른 캐시 폴더에 받아지고 실행됨.
- T11 홈과 속도: 다른 홈(37.5665, 126.9780, 30, 90)으로 시작해 위치 확인, 속도 배수 4로 프로세스 인자에 `--speedup 4`.
- T12 값 초기화: 파라미터 하나를 바꿔 쓰고 정지·재시작하면 유지, 값 초기화로 시작하면 기본값.
- T13 다른 연결 중: 가짜 기체를 연결하면 배너와 시작 비활성, 끊으면 풀림.
- T14 SITL이 죽음: 테스터가 프로세스를 강제로 끝내면 `Failed`, 배너 "시뮬레이터가 멈췄어요"(종료 코드 글은 없어도 됨), 링크 닫힘, 다시 시작 가능. UDP 14550을 다른 프로그램이 쥐고 있으면 `LinkFailed`와 SITL 프로세스 없음.
- T15 실행 중 링크만 끊기: 상단 연결 단추로 끊으면 "연결이 끊겼어요"와 "다시 연결", 누르면 다시 붙음. 상단 단추로 다시 열어도 "UDP 14550으로 연결했어요". 시리얼 포트를 고른 채 시작해도 상단 포트 칸은 UDP 14550.
- T16 앱 종료: 실행 중 창을 닫으면 SITL 프로세스가 남지 않음.
- T17 인터넷 없음(`net='refuse'`): `Failed`와 문구, 캐시 폴더에 `.part-*` 없음. 인터넷을 켜고 다시 시작하면 성공.
- T18 내려받기 취소: 진행 중 취소하면 `Idle`, `.part-*` 없음.
- T19 기억: 앱을 다시 켜면 마지막 기체·배포판·홈·속도가 그대로, 값 초기화는 꺼짐. "해운대로 되돌리기"가 기본값을 채움. 범위 밖 입력은 빨간 글과 시작 비활성.
- T20 출력: 실행 중 출력 상자에 SITL 출력 줄이 보이고 200줄을 넘으면 앞이 잘림. 한국어·영어, 네 테마 화면(xcb), 글자 대비.
