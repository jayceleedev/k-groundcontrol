## 1. 목적
2단계(펌웨어 선택)에서 FC가 USB로 알려 준 보드 이름과 공식 빌드 이름을 맞춰 본 결과를 먼저 보여 준다. 맞는 빌드가 하나면 골라 둔다. 결과가 마음에 들지 않거나 맞는 빌드가 없으면 검색창에서 보드를 직접 고른다. 보드 ID가 다른 빌드는 회색으로 보이기만 하고 고를 수 없다.

## 2. 사용자 결정 (2026-11-04)
1. 인식 결과를 먼저 보여 주고, 마음에 안 들면 검색창으로 직접 고른다.
2. 보드 ID가 다른 빌드는 검색에 회색으로 보여 준다(고를 수 없음). 0.2.0의 "보드 ID가 다르면 굽지 않고 우회 없음"은 그대로다.

### 5.1 `comm/links` USB 보드 이름
- `PortInfo`에 `QString usbName`을 더한다. USB 장치가 스스로 알려 준 제품 이름을 **그대로**(앞뒤 공백만 제거, `-BL` 같은 꼬리를 떼지 않는다) 담는다. 모르면 빈 값. 2단계에서 FC는 부트로더이므로 부트로더의 이름이다(KOA FC는 "KoaFC", 서버 커널 기록 2026-11-04 19:21, `3162:004b`, 제조사 Koadrone).
  - Linux: 순수 함수 `QString usbNameFromSysfs(const QString& sysRoot, const QString& ttyName)`. `<sysRoot>/class/tty/<ttyName>/device`의 심볼릭 링크를 `canonicalFilePath`로 풀고, 그 폴더부터 부모로 올라가며 `idVendor` 파일이 있는 첫 폴더의 `product`를 읽는다. `sysRoot`(풀린 경로 기준) 위로는 올라가지 않는다. 링크가 없거나 못 찾으면 빈 값. 앱은 `sysRoot = "/sys"`, `ttyName`은 `/dev/`를 뺀 이름.
  - Windows: `SetupDiGetClassDevsW(&GUID_DEVCLASS_PORTS, nullptr, nullptr, DIGCF_PRESENT)`로 훑어, 장치 레지스트리 값 `PortName`이 그 COM 이름인 노드의 `DEVPKEY_Device_BusReportedDeviceDesc`. 비었으면 `CM_Get_Parent`로 얻은 부모 노드의 같은 값. 그것도 비면 빈 값. 라이브러리 `setupapi`(와 `cfgmgr32`)는 Windows에서만 `kgc_comm_links`에 PRIVATE로 링크한다.
  - PTY 같은 USB가 아닌 포트는 빈 값.
- 파일은 `comm/links/serial/UsbName.{h,cpp}`, 이름공간 `kgc::comm::links`. `usbNameFromSysfs`는 모든 OS에서 빌드되고(시험도 Linux·Windows 둘 다 돈다), 앱에서 부르는 곳만 Linux다. Windows 조회 함수 `usbNameWindows(portName)`은 `#ifdef Q_OS_WIN` 안에 둔다. `LinkManager::portInfo`가 OS에 맞는 쪽을 부른다.

### 5.2 자료 `px4-boards.json`에 이름 더하기
- PM이 PX4 v1.17.0 `boards/<제조사>/<모델>/nuttx-config/*/defconfig`의 `CONFIG_CDCACM_PRODUCTSTR` 값을 모아 항목마다 `"names": [...]`로 더해 저장소에 넣어 둔다(예: `{"boardId":1013,"prefix":"matek_h743","names":["Matek H743-slim","MatekH743"]}`). 값이 없는 보드는 빈 목록이다(98개 중 76개에 있음). 만든 파일은 `.pm/0.4.1/px4-boards.json`이고, 승인 뒤 PM이 `resources/data/fcflash/px4-boards.json`을 바꾼다. 구현자는 이 파일을 고치지 않는다.

### 5.3 `fcFlash` 순수 함수 (`internal/sources/BoardMatch.{h,cpp}`)
- `bool nameMatches(const QString& usbName, const QStringList& names)`: 둘 다 앞뒤 공백을 빼고 대소문자를 무시해 같은 값이 하나라도 있으면 참. `usbName`이 비면 거짓.
- `enum class BoardMatch { NoName, Matched, NoMatch }` (`api/kgc/fcFlash/FlashStates.h`에 두어 QML이 읽는다).
- `MatchResult recognize(const QString& usbName, const QList<QStringList>& candidateNames)`: `candidateNames`는 같은 보드 ID 후보마다 맞춰 볼 이름 목록이다. 결과 `{BoardMatch kind; QList<int> matched;}`.
  - `usbName`이 비면 `NoName`, `matched` 빈 값.
  - 하나 이상 맞으면 `Matched`, `matched`는 맞은 후보의 위치(목록 순서).
  - 아무것도 안 맞으면 `NoMatch`.
- `int preselect(const MatchResult&, int count)`: `Matched`이고 맞은 후보가 하나면 그 위치. `NoName`이면 0.2.0 규칙(`pickCandidate(count) == Auto`면 0). 그 밖은 −1(선택 없음).
- 보드 ID 255(fmu-v3)는 0.2.0처럼 어떤 경우에도 미리 고르지 않는다. 지금 `rebuildCandidates`의 255 검사를 `preselect` 바깥에 그대로 둔다(`Matched` 하나여도 −1).
- 맞춰 볼 이름: ArduPilot 후보는 `platform`과 목록 항목의 `bootloader_str` 전부. PX4 후보는 그 `prefix`의 `names`.
- 같은 보드 ID인지는 0.2.0 `compatible(boardId, otherId)`로 본다(9와 255는 같다). 행 칩의 "보드 ID %1"은 같은 보드 ID 후보면 FC의 보드 ID, 다른 보드면 그 빌드의 보드 ID다.

### 5.4 다른 보드 목록
새 형(모두 `internal/sources/`):
- `struct OtherBoard { QString name; int boardId; }` — 화면에 낼 다른 보드 한 행.
- `struct ManifestBoard { QString platform; int boardId; ArduPilotVehicle vehicle; QString buildType; }`.
- `struct ManifestScan { QList<ManifestEntry> entries; QList<ManifestBoard> boards; }`.
- `struct Px4Board { int boardId; QString prefix; QStringList names; }`.

함수:
- `ManifestScan scanManifest(const QByteArray& bytes, int boardId)`: `entries`는 0.2.0과 같다. `boards`는 보드 ID가 `compatible`하지 않은 `apj` 항목에서 0.2.0의 기체·빌드 종류 조건을 통과한 것의 `platform`, `board_id`, 기체, 빌드 종류. 이 항목들은 `QJsonDocument`로 만들지 않고 필드 값을 바로 읽는다. `(platform, boardId, vehicle, buildType)`이 같으면 한 번만.
- `ManifestEntry`에 `QStringList bootloaderNames`(`bootloader_str`)를 더한다.
- `QList<OtherBoard> manifestOtherBoards(const ManifestScan&, ArduPilotVehicle, const QString& buildType)`: 그 기체·빌드 종류의 `boards`를 `{platform, boardId}`로. 같은 보드 ID 후보와 `platform`이 같은 행은 뺀다. 한 `platform`이 여러 보드 ID에 있으면(KakuteF4 70·122 등) 보드 ID마다 한 행.
- `QList<Px4Board> px4Boards(const QByteArray& boardsJson)`: `px4-boards.json` 전부. `px4Prefixes`는 이것을 써서 지금 동작을 유지한다.
- `QList<OtherBoard> px4OtherBoards(const Px4Release&, const QList<Px4Board>&, int boardId)`: 릴리스 자산 중 `compatible`하지 않은 보드의 `prefix`에 맞는 `<prefix>_<꼬리표>.px4`(꼬리표 `bootloader` 제외)를 `{"<prefix> · <꼬리표>", 그 보드 ID}`로. `px4-boards.json`에 없는 자산은 뺀다.
- 정렬은 둘 다 이름을 대소문자 무시(`Qt::CaseInsensitive`)로, 같으면 보드 ID 작은 순.

`manifestScanned` 시그널과 보드 ID별 `manifests` 캐시는 `ManifestScan`을 싣는다. 목록은 지금처럼 앱이 켜져 있는 동안 메모리에 둔다. 해석은 작업 스레드에서 한다.

### 5.5 서비스와 컨트롤러
`FcFlashService`와 `FcFlashController`에 프로퍼티를 더한다(값은 그대로 넘긴다).
- `usbName`(QString): 보드 확인 때 `portInfo(port).usbName`. 0.2.0이 `usb`를 읽는 그 자리에서 같이 읽는다.
- `matchKind`(`BoardMatch`), `matchedCandidates`(QList<int>): 후보가 바뀔 때마다 `recognize`로 다시 낸다.
- `otherBoards`(QVariantList, 항목 `{name, boardId}`): 지금 출처·기체·버전의 다른 보드 목록, 이름 순.
- `candidateIndex`의 처음 값은 `preselect` 결과다. 사용자가 고르면 `chooseCandidate(index)`(지금과 같다). 다른 보드 행은 고를 수 없으므로 서비스 함수는 더하지 않는다.
- `FcFlashController`에만 읽고 쓰는 프로퍼티 `showOtherBoards`(bool, 기본 false)를 더한다. 화면 상태라 서비스에는 두지 않는다. 컨트롤러는 C++이 앱 끝까지 쥐므로 패널을 닫았다 열어도 값이 남는다.

### 6.3 검색과 목록 (`fcFlashBoardSearch`, `fcFlashOtherBoards`, `fcFlashBoardList`)
- 검색 줄과 목록은 0.2.0의 후보 표와 같은 때만 보인다: 파일 선택이 아니고, 목록을 받는 중이 아니고, 받기에 실패하지 않았고, 같은 보드 ID 후보가 하나 이상. 그 밖에는 숨기고 §6.2와 0.2.0 배너("목록을 받지 못했어요…", "공식 목록에 이 보드용 펌웨어가 없어요…")만 보인다. 두 배너는 지금처럼 `Banner` 하나를 같이 쓰고, `NoMatch` 배너는 따로 하나 둔다.
- 한 줄에 `SearchBox`(자리 글자 "보드 이름 검색")와 `CheckRow` "다른 보드 ID도 보기"(`tristate: false`, `checked`는 `FcFlashController.showOtherBoards`에 묶는다). 검색어는 QML 안에만 두고 2단계에 다시 들어오면 빈다.
- 목록 행은 `RadioRow`. 행 오른쪽에 `Chip`.
  - 같은 보드 ID 후보: 고를 수 있다. `Chip` level ok "보드 ID %1". 맞은 후보는 그 앞에 `Chip` level ok "인식됨"을 하나 더 단다.
  - 다른 보드(체크했을 때만): `enabled: false`, `Chip` level idle "보드 ID %1 · 구울 수 없음".
- 순서: 맞은 후보 → 나머지 같은 보드 ID 후보(지금 순서) → 다른 보드(`otherBoards` 순서, §5.4 정렬).
- 다른 보드 행 글자는 비활성 `RadioRow`의 색(`Theme.inkDisabled`)이고 칩은 level idle다. 테마 넷에서 바탕과 대비 3:1 이상이어야 한다(T12). 안 되면 멈추고 보고한다(토큰을 더하지 않는다).
- 검색: 대소문자를 무시한 부분 일치, 입력할 때마다 거른다. 빈 검색어는 전부. 걸러져도 고른 후보는 그대로 고른 상태다(행이 숨어도 `다음`이 된다).
- 걸러서 아무 행도 없으면 `EmptyState` "검색어와 맞는 보드가 없어요".
- 목록 높이는 패널 안에서 행 8개까지 보이고 그 뒤는 목록 안에서 스크롤한다(PX4·ArduPilot 다른 보드는 수백 개다).
- 행 objectName: 같은 보드 ID 후보 `fcFlashCandidate_<후보 위치>`, 다른 보드 `fcFlashOther_<이름>_<보드 ID>`.

### 저장소 테스트 (`tests/`)
- **T1** `nameMatches`: 대소문자·앞뒤 공백 무시, 빈 이름 거짓, 부분 일치는 거짓("MatekH743"와 "MatekH743-bdshot").
- **T2** `recognize`·`preselect`: `NoName`(후보 0·1·여럿은 0.2.0과 같음), `Matched` 하나(그 위치), `Matched` 여럿(−1), `NoMatch`(−1).
- **T3** `scanManifest`·`manifestOtherBoards` 표본: `bootloaderNames`가 채워지고, 다른 보드 ID 항목이 기체·빌드 종류별로 한 번씩, 한 `platform`이 두 보드 ID에 있으면 두 행, 같은 보드 ID 후보와 이름이 같은 행은 빠지고, 9·255는 다른 보드로 안 나오며, 대소문자 무시 정렬. `entries`는 0.2.0과 같다.
- **T4** `px4Boards`·`px4OtherBoards`: `names`가 있는 표본을 읽고, 표본 릴리스에서 다른 보드 ID 자산만, `bootloader` 제외, `px4-boards.json`에 없는 자산 제외. `px4Prefixes`의 결과는 0.2.0과 같다.
- **T5** `usbNameFromSysfs`: 실제 모양의 가짜 sysfs(`devices/.../1-6/{idVendor,product}`, `devices/.../1-6/1-6:1.0/tty/ttyACM0`, 그곳을 가리키는 심볼릭 링크 `class/tty/ttyACM0/device`)에서 `product`를 읽는다. 링크가 없거나 `idVendor`가 `sysRoot` 안에 없으면 빈 값. 심볼릭 링크를 못 만드는 Windows 시험 환경에서는 이 경우를 건너뛴다(`QSKIP`).

### 검사

### 앱 (가짜 부트로더, 실제 인터넷)
- **T7** `NoName`: ArduPilot Copter 안정판, 보드 ID 1013 → 인식 줄은 "맞는 펌웨어 2개. 직접 골라요.", 목록에 MatekH743·MatekH743-bdshot이 고를 수 있게 나오고 미리 고른 것 없음.
- **T8** "다른 보드 ID도 보기": 켜면 다른 보드가 회색 행으로 나오고 눌러도 선택이 바뀌지 않는다. 두 번 누르면 꺼지고(세 번째 상태 없음) 사라진다. 출처를 PX4로 바꿔도, 다른 패널에 갔다 와도 켜진 채다.
- **T9** 검색: "matek"으로 거르면 Matek 행만, "zzz"는 빈 목록 안내. 고른 뒤 걸러서 행이 숨어도 `다음`이 되고 3단계에 그 빌드가 나온다.
- **T10** PX4: 같은 화면 규칙으로 보드 ID 1013의 다섯 `prefix`(`hkust_nxt-dual`, `hkust_nxt-v1`, `matek_h743`, `matek_h743-mini`, `matek_h743-slim`) 중 릴리스에 있는 자산이 고를 수 있게 나오고, 다른 보드 목록이 회색으로 나온다.
- **T11** 앱을 새로 켜고 ArduPilot을 처음 눌러 목록을 받을 때: 목록 해석 중 GUI 멈춤 100ms 미만(0.2.0 T23과 같은 방법), 내려받기가 끝난 로그 줄부터 후보 목록이 보일 때까지 10초 안(시험 서버 기준). 0.4.0 빌드의 같은 시간도 함께 적는다(참고값, 합격 조건 아님).
- **T12** 언어 전환과 테마 넷: 새 문구가 재시작 없이 영어로. 테마 넷의 스크린숏에서 회색 행 글자와 칩 글자의 바탕 대비가 3:1 이상(색 값으로 계산), 화면이 그림 `stepFirmwareMatched`·`stepFirmwareNoMatch`의 배치와 같다.
