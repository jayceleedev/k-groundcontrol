## 1. 목적
0.5.0 지도는 두 까닭으로 흐리게 보인다(Qt Location 6.12 소스로 확인, 조사 `dpr-tiles.md`·`code-map.md` §1.3).
1. **소수 확대**: 확대가 14.6이면 Qt는 14층 타일을 받아 2^0.6 = 1.52배로 늘려 그린다(내림, 최대 2배 가까이). 휠은 `angleDelta.y / 120`씩 더해 정밀 터치패드의 작은 값이 소수를 남기고, 핀치는 끝나도 소수 그대로이며, 보던 곳 저장으로 다음 실행에도 남는다.
2. **화면 배율**: Windows 125·150 %에서는 256 px 타일이 화면 320·384 화소로 늘어난다. 확대가 정수이면 Qt는 가장 가까운 화소로 늘려(Nearest) 글자와 선이 계단처럼 깨진다. 시험 사진에서 기준 그림과의 차이(RMSE)가 배율 1.25·1.5에서 21.7·23.4였다.

고침: (가) 확대를 정수 층에 맞춘다, (나) 화면 배율이 문턱(§2 (나)) 이상이면 2배 해상도 타일(512 px)을 받아 같은 칸에 그린다(같은 시험에서 RMSE 9.2·9.0, 계단 없음).

## 2. 사용자 결정 (2026-11-27)과 PM이 정한 규칙
1. (가) **정수 확대.** 휠과 확대·축소 단추는 그 방향의 다음 정수 층으로(14.6에서 확대 → 15, 축소 → 14), 핀치는 끝날 때 가까운 정수 층으로 맞춘다. PM 규칙:
   - 휠 값은 모아서 120(마우스 한 칸)마다 한 층. 한 번의 몸짓(휠이 0.25초 넘게 쉬기 전까지) 안에 120의 배수가 아닌 값이 한 번이라도 오면 그 몸짓은 끝까지 "잔 값 흐름"(정밀 터치패드·부드러운 휠)으로 보고, 한 층을 넘긴 뒤 130 ms가 지나야 다음 층으로 간다(터치패드 한 번 쓸기에 열 몇 층이 넘어가지 않게, 빨라도 초당 일곱 층쯤). 방향이 바뀌면 모은 값을 버린다. Windows Qt 6.12에서는 정밀 터치패드의 두 손가락 쓸기와 핀치가 모두 휠 사건(핀치는 Ctrl)으로 오므로 이 규칙 하나가 둘 다 맡는다(조사 `windows-input.md` F1·F2).
   - 모은 값이 120에 못 미치면 아무 일도 없다(Windows 정밀 터치패드는 패드 높이의 약 1/5 미만으로 쓸 때). 스치는 손에 확대가 바뀌지 않게 하려는 것이다(받아들임).
   - 핀치(터치 화면, Linux 터치패드)는 하는 동안은 부드럽게 바뀌고, 끝날 때 가까운 정수 층으로 애니메이션 없이 바로 맞춘다. 0.3층 넘게 움직였는데 반올림이 시작 층으로 돌아가면 움직인 방향으로 한 층 간다(일부러 조금 오므린 것이 되돌아가지 않게).
   - 예외: 지도 폭에 맞춘 Qt의 최소 확대(1440 px 폭이면 2.49)는 소수 그대로 쓴다. 그보다 작은 정수로는 못 가고, Qt가 창이 커질 때 스스로 올리는 값이라서다. 창이 줄어 최소 확대가 내려가면 그때의 소수 확대는 다음 휠·단추까지 그대로다(받아들임). 이 확대들에서는 지도가 너무 작아 흐림이 보이지 않는다.
   - 시작할 때 저장된 확대가 소수면(0.5.0이 남긴 14.6 등) 가까운 정수로 반올림해 연다.
   - 휠 모음은 지도 부품마다 따로다. 키보드 확대는 없다(0.5.0 그대로).
2. (나) **2배 해상도 타일.** 화면 배율이 문턱 `kHighDpiMinRatio` 이상이면 Google 주소에 `&scale=2`를 붙여 512 px 타일을 받고 지금의 256 칸에 그린다(Qt가 줄여 그리고 부드럽게 거름). PM 규칙:
   - 배율은 연결된 모든 화면의 `QScreen::devicePixelRatio()` 가운데 가장 큰 값으로 정한다. 노트북(150 %)에 바깥 모니터(100 %)를 이으면 둘 다 2배 타일이다(100 %에서는 아주 조금 부드러워질 뿐, 조사 `dpr-tiles.md` §5). 창을 다른 화면으로 옮겨도 바뀌지 않고, 화면을 더하거나 빼거나 배율을 바꾸면 다시 정한다.
   - 문턱: 1.15(115 %) 이상만 2배다(승인 때 사용자 결정, 처음 결정 "100 %보다 크면"을 바꿈). Windows 125·150 %와 사용자 지정 120 %(DPI 115, 1.198)는 2배, Windows 110 %(1.10)나 Linux Xft 100 dpi(1.04)는 1배다(4배 공간을 쓰는 데 비해 나아짐이 작음).
   - 1배와 2배 타일은 저장소 키가 다르다(2배는 키 끝에 `@2`). 0.5.0이 저장한 타일과 받은 영역(1배 키)은 그대로 남는다.
   - 보기 요청은 다른 배수의 저장된 타일을 대신 보여 줄 수 있다: 오프라인일 때는 서버에 묻기 전에, 온라인일 때는 서버가 실패한 뒤에(503 등). 그래서 0.5.0에서 받은 영역을 2배 화면에서 오프라인으로 바로 볼 수 있다. 다시 온라인이 되면 대신 보여 준 칸은 지금 배수로 다시 청한다. 영역 받기는 지금 배수로만 받는다(대신 쓰지 않음).
   - 2배 화면에서 같은 영역을 다시 받으면 1배·2배 사본이 둘 다 남고("미리 받은 것" 크기에 둘 다 들어감) 비우기로만 지워진다. 2배 받기는 같은 타일 수에 약 4배 공간을 쓴다(위성 100,000개면 약 5.9 GB). 크기 어림도 4배로 잡는다(타일 바이트가 약 4배라는 보고, 조사 `reference-gcs.md` §3.2). 저장 한도 기본값(2048 MB)은 그대로다(2배 화면에서는 타일 수로 약 ¼까지 담는다).
   - 2배 타일은 보이는 칸마다 GPU 약 1.3 MiB·CPU 그림 1 MiB를 쓰고(1440×1000 지도 약 35칸이면 GPU 약 47 MiB), GUI 스레드의 그림 풀기도 장당 약 4배다. Qt 텍스처 캐시가 화면 밖 칸을 0.5.0보다 적게 들어, 되돌아가면 메모리 캐시·저장소에서 다시 푼다(받아들임).
   - Google `/vt`의 `scale=2`는 공개 자료로만 확인했다(위성·하이브리드는 실제로 더 촘촘한 그림, 글자 크기는 같음). U1에서 2배 화면에서만 "Request failed: mt…google.com, HTTP 4xx"가 나오거나 글자가 0.5.0보다 커지면 사용자에게 다시 묻는다(0.5.0 §2의 403 규칙과 같음).

## 3. 범위 밖
- `scale=4`(배율 300 % 이상 화면 전용), 창마다 다른 배수.
- 이 고침을 끄는 설정 항목(자동만).
- Qt 6.13의 Windows 터치패드 Direct Manipulation(핀치가 PinchHandler로 오는 길). 이 규칙은 그때도 그대로 맞지만 시험하지 않는다.
- 확대 막대·확대 칸 같은 새 조작부.
- 같은 배수에서 배율만 바뀔 때(예: 200 % ↔ 150 % 모니터 사이로 창을 옮김)의 Qt 거름 갱신. 이미 보이는 칸은 층이 바뀌거나 화면에서 나갔다 들어올 때까지(끌기만으로는 아님) 예전 거름으로 그려지고, 핀치 중 Qt 경고 "Mipmap settings changed…"가 앱 로그(`kgc.qt`)에 남을 수 있다(받아들임).
- 온라인인 채 서버 실패(503 등)로 대신 보여 준 칸은 Qt 캐시에서 밀려나거나, 언어·배수가 바뀌거나(판 올림), 다음에 오프라인에서 다시 온라인이 될 때까지 남는다. 층이나 종류를 바꿨다 돌아와도 같은 그림이다(받아들임).
- 대신 쓴 뒤 다시 닿으면(판 올림) 보이는 칸이 모두 잠깐 비었다가 저장소·서버에서 다시 채워진다. 연결이 오락가락하면 다시 닿을 때마다 되풀이되고, 서버가 필요한 칸은 그 사이 끊기면 `kTileTimeout`(10초)까지 비어 있다가 다시 대신 쓴 그림이 된다(받아들임).

## 5. 기반 — 더하는 것과 바꾸는 것

### 5.1 순수 함수 `features/map/internal/ZoomStep.{h,cpp}` (이름공간 `kgc::map`, 새 파일)
- `struct WheelStep { int steps = 0; double sum = 0; bool fine = false; };`
- `WheelStep wheelStep(double sum, bool fine, int delta, qint64 sinceStepMs)` — 휠 사건 하나를 모은 값에 더해 몇 층 갈지 정한다. `sum`은 이 몸짓에서 모은 값, `fine`은 이 몸짓이 잔 값 흐름인지, `delta`는 `angleDelta.y`, `sinceStepMs`는 이 지도 부품이 마지막으로 층을 넘긴 뒤 지난 시간.
  1. `delta == 0`이면 `{0, sum, fine}`.
  2. `fine = fine || delta % kWheelNotch != 0`.
  3. `sum`이 0이 아니고 `delta`와 부호가 다르면 `sum = 0`.
  4. `sum += delta`. `sinceStepMs < 0`이면(시계가 뒤로 감) 아주 큰 값으로 본다.
  5. `!fine`이면(마우스 칸, Windows 터치패드 핀치): `steps = trunc(sum / kWheelNotch)`, `sum -= steps * kWheelNotch`.
  6. `fine`이면: `|sum| >= kWheelNotch`일 때, `sinceStepMs >= kWheelStepIntervalMs`이면 `steps = sign(sum)`, `sum -= steps * kWheelNotch`; 아니면 `sum = sign(sum) * kWheelNotch`(넘는 만큼 버려 손을 뗀 뒤에 층이 더 넘어가지 않게).
  7. `{steps, sum, fine}`를 돌려준다.
- `double zoomStepTarget(double current, int steps, double minZoom, double maxZoom)` — 지금 확대에서 `steps`만큼 정수 층을 옮긴 값. `steps > 0`이면 `floor(current + kZoomEpsilon) + steps`, `steps < 0`이면 `ceil(current - kZoomEpsilon) + steps`, `0`이면 `current`. 끝에 `[minZoom, maxZoom]`으로 자른다(아래쪽은 소수일 수 있다, §2 예외).
- `double pinchSnapTarget(double startZoom, double endZoom, double minZoom, double maxZoom)` — 핀치가 끝났을 때 맞출 층. `r = std::round(endZoom)`. `r == std::round(startZoom)`이고 `|endZoom - startZoom| >= kPinchSnapMin`이면 `r = zoomStepTarget(startZoom, endZoom > startZoom ? 1 : -1, minZoom, maxZoom)`. 끝에 `[minZoom, maxZoom]`으로 자른다.
- `int tilePixelRatioFor(double screenRatio)` — `screenRatio >= kHighDpiMinRatio`이면 2, 아니면 1.
- 시험 §8 T1.

### 5.3 `tileUrl`·`tileKey` (`internal/TileUrl.{h,cpp}`, §5.6.3을 바꿈)
- `QString tileUrl(settings::MapType type, const QString& language, int ratio, int z, int x, int y, const QString& host)` — 0.5.0 주소 뒤에 `ratio == 2`일 때만 `&scale=2`. `ratio == 1`의 주소는 0.5.0과 한 글자도 다르지 않다.
- `QString tileKey(settings::MapType type, const QString& language, int ratio, int z, int x, int y)` — 0.5.0 키 뒤에 `ratio == 2`일 때만 `@2`. 1배 키는 0.5.0과 같다(저장된 행·받은 영역이 그대로 쓰인다).
- `ratio`는 1 또는 2(다른 값은 `Q_ASSERT`). 다른 배수는 `ratio == 1 ? 2 : 1`로 쓴다.

### 5.4 `TileSource` (§5.6.6을 바꿈)
- 공개: `int tilePixelRatio() const;`, `void setTilePixelRatio(int ratio);`(같은 값이면 아무것도 안 함, 다르면 `tilePixelRatioChanged`), 신호 `void tilePixelRatioChanged();`, `void fallbackStale();`. 처음 배수 1.
- `TileTicket fetch(settings::MapType type, const QString& language, int ratio, int z, int x, int y, bool pin, Done done)` — 키·주소에 `ratio`를 쓴다.
- `Pending`에 필드 `int ratio`와 `std::optional<ErrorCode> fallbackError`(비면 "서버에 묻기 전"), 단계에 `Fallback`. 비공개 멤버 `bool fallbackServed_`(대신 쓰기로 그림을 준 적이 있음), 도우미 `void startFallback(const QString& key)`(`pending_`에 있는 그 대기를 `Fallback` 단계로 두고 `request`를 비운 뒤 새 `requestId`로 다른 배수 키를 `lookup`). 멤버 `int tilePixelRatio_`(지금 배수).
- 주소: `startHttp`의 주소와 `httpFinished`의 `reach(false, …)` 주소(서버 다시 묻기)는 대기의 `ratio`로 만든다. 다른 배수 키는 `tileKey(type, language, ratio == 1 ? 2 : 1, z, x, y)`(대기의 값, 지금 공급 배수가 아님).
- **다른 배수 대신 쓰기**:
  1. 서버에 묻기 전(오프라인): `storeMissing`이 `Lookup` 단계에 오고 `online_`이 거짓이며 기다리는 사람이 모두 `pin` 거짓이면, `fallbackError`를 비운 채 `startFallback`. 아니면 0.5.0처럼 `startHttp`.
  2. 서버가 실패한 뒤: `httpFinished`의 두 실패 갈래(그림이 아닌 200, 오류)에서 기다리는 사람 가운데 `pin` 거짓이 있으면, 대기를 지우지 않고 그 `fallbackError`를 그 실패로 정한 뒤 `startFallback(key)`. 모두 `pin`이면(영역 받기만) 0.5.0처럼 대기를 지우고 바로 실패(지우는 것은 이 갈래와 성공 갈래뿐). `reach` 처리는 두 경우 모두 지금처럼 바로 한다. 서버에 묻기 전에 이미 다른 배수를 찾지 못한 대기도 한 번 더 찾는다(받아들임).
  3. `storeFound`가 `Fallback` 단계에 오면: `fallbackError`가 비었는데 그 사이 `online_`이 참이 되었으면(찾는 동안 다시 닿음) 찾은 바이트는 버리고 `startHttp(key)`를 한다. 아니면 `fallbackServed_ = true`, `pin` 거짓인 사람에게 그 바이트를 보낸다(저장·고정 안 함). `pin`인 사람은 `fallbackError`가 비었으면 대기에 남겨 `startHttp`(서버에 아직 안 물었으므로), 있으면 `deliverFailure(key, …, *fallbackError)`.
  4. `storeMissing`이 `Fallback` 단계에 오면: `fallbackError`가 비었으면 `startHttp(key)`, 있으면 모두에게 `deliverFailure(key, waiters, *fallbackError)`.
  5. `cancel`은 `Fallback` 단계도 `Lookup`처럼 한다(대기만 지우고 멈출 요청 없음, 늦은 저장소 답은 `requestId`가 맞지 않아 버려짐). `storeEntry`·`storeFound`·`storeMissing`은 `Fallback` 단계를 받는다. `Fallback` 대기에 나중에 낀 사람도 같은 규칙을 따른다.
  6. "Tile failed" 로그는 지금처럼 최종 실패 때 키마다 한 번.
- `reach(true)`가 오프라인에서 온라인으로 바뀌면: `fallbackServed_`가 참이면 `onlineAgain()` 대신 `fallbackStale()`을 내고 거짓으로 되돌린다(판 올림이 보이는 칸을 모두 다시 청하므로 빈 칸 다시 청하기가 따로 필요 없음). 거짓이면 0.5.0처럼 `onlineAgain()`.

## 6. 동작 요약 (사용자가 보는 것)
- 휠 한 칸·확대 단추는 언제나 정수 층으로 간다. 터치패드 두 손가락 쓸기는 짧게 쓸면 한 층, 길게 쓸면 여러 층(빨라도 초당 일곱 층을 넘지 않음)이고, 손을 멈추면 바로 멈춘다. 아주 짧게 스치면 아무 일도 없다. 터치패드·화면 핀치는 손을 떼면 가까운 층으로 딱 맞춰진다.
- 배율 125 %·150 % 화면에서 지도 글자와 선이 계단 없이 매끈하다(글자 크기는 같음). 100 % 화면에서는 0.5.0과 같다.
- 2배 화면에서도 0.5.0에서 받아 둔 영역을 오프라인으로 바로 볼 수 있고(1배 그림), 다시 온라인이 되면 지도가 잠깐 비었다가 선명한 그림으로 다시 채워진다.
- 2배 화면에서 영역을 받으면 같은 타일 수에 약 4배 공간을 쓰고, 어림 크기도 4배로 보인다.
